# テーマ切替・表示色設定 業務仕様書

## 1. 概要

アプリ全体の色調を **ライト / ダーク / OS の設定に従う** の 3 通りから選択できる機能。設定は **個人 preference（端末ごとの好み）として扱い**、サインインしているアカウントには紐付けず、利用中の端末のブラウザにのみ保存される。ダークモードは「深ネイビーを基調にしたシックな配色」で、長時間視認するタイマー画面や会場の暗所投影でも目に優しいトーンに整えてある。テーマ選択は [/settings](/settings) 画面の「テーマ」セクションで切り替える。設定はサインインしていなくても保存されるが、トグル UI に到達するには通常アカウントでのサインインが必要（[/settings](/settings) は通常アカウント / ゲスト匿名の両方で閲覧可能）。サインアウト状態・初回利用時の既定値は「OS の設定に従う」で、Android Chrome や iOS Safari のシステム設定（ダーク / ライト）に追従する。アプリのテーマ切替に連動して、QR コードの色味と、トーナメント終了時の優勝者バナーの装飾も読みやすさを保つよう自動調整される。

## 2. 想定利用シーン

### 2.1 ペルソナ

- **会場運営する運営担当者**: 暗い会場でタイマーを大画面投影中。眩しすぎるライトモードを避けたい
- **長時間スマホで運営する人**: 月例運営でスマホ画面を長く見るため、夜間は OS のダークモード追従でアプリも自動で暗くなってほしい人
- **デザインの好みでライトを使い続けたい人**: 端末 OS はダークモードだが、アプリだけはライトモードのままで使いたい人
- **ゲスト参加者（匿名）**: アプリ自体をその場だけ使うが、自分のスマホの OS 設定（ダーク）に追従して欲しい人

### 2.2 シナリオ

#### 2.2.1 平常系: OS 設定に追従して自動で暗くなる

新メンバー A さんが初めて ALLin-PokerTimer を Android Chrome で開く → 端末の OS が夜間ダークモードになっている → アプリも自動でダークパレットで表示される → サインインや明示的な操作は一切不要。OS の昼夜切替に追従して、アプリの色も自動で切り替わる。

#### 2.2.2 平常系: ライト固定に切り替え

運営担当者 B さんが、屋外イベントで日中に開催 → 会場が明るすぎてダーク UI が見にくい → [/settings](/settings) を開く → 「テーマ」セクションの「ライトモード」アイコンをタップ → 即座にアプリ全体がライト配色に切り替わる → 設定はこの端末のブラウザに保存され、次回アプリを開いてもライトのまま。

#### 2.2.3 平常系: 端末ごとに別設定

オーナー C さんは普段スマホでは「ダーク固定」、会場の運営用ノート PC では「OS 設定追従」で使う。両端末で別々の設定を保存でき、アカウントを共有していても端末ごとの好みが優先される。

#### 2.2.4 失敗系: 初回起動時の表示ちらつき（FOUC）

新メンバー D さんが iPhone Safari でアプリを開いた瞬間に、まず一瞬ライト画面が出てから暗くなる…ような **チラつき** は発生しない仕様。アプリは画面描画の前に保存済みの設定を読み取り、最初のフレームから正しい色で表示する。

#### 2.2.5 失敗系: ブラウザの設定でローカル保存が無効

E さんが「サイトデータ保存を一切許可しない」ブラウザ設定にしている → 端末の OS 設定（ダーク / ライト）に毎回追従するモードに自動でフォールバック → 明示切替は記憶されないが、アプリ自体は問題なく動作する。

#### 2.2.6 運用系: ゲスト匿名のままで使う

匿名ゲストの F さんがトーナメント受付に来る → スマホは OS でダークモード → アプリも自動でダーク → そのままトーナメントに参加。[/settings](/settings) はゲスト匿名でも開けるため、F さんも明示切替は可能だが、運用上はサインアウト状態 / 匿名でも OS 追従で自然に動く。

## 3. 機能要件

### 3.1 テーマの選択（ライト / ダーク / OS の設定に従う）

#### 3.1.1 何ができる機能か

- [/settings](/settings) 画面に「テーマ」セクションがあり、3 つのアイコンボタン（太陽 = ライト / 月 = ダーク / モニタ = OS の設定に従う）から 1 つを選べる
- 選択した瞬間にアプリ全体の色調が切り替わる（ヘッダー、サイドバー、カード、ボタン、入力欄、グラデーション、QR コードまで連動）
- 設定は **この端末のブラウザにのみ保存** される（アカウントには紐付かない）
- 「OS の設定に従う」を選ぶと、端末の昼夜モード変更にアプリも自動で追従する

#### 3.1.2 誰が・いつ使うか

- 全ユーザー（サインインの有無・役割にかかわらず）。ただし [/settings](/settings) 画面に到達するにはサインイン（通常アカウントまたはゲスト匿名）が必要
- 端末を初めて使うときに 1 度設定すれば、以降は記憶される
- 屋内 / 屋外の利用環境を変えたとき、OS の昼夜モードを変えたとき

#### 3.1.3 なぜこの機能が必要か（Why）

会場の照明環境はサークルごとに大きく異なる（明るいスタジオ / 暗いバー / 屋外昼間など）。長時間視認するタイマー画面が眩しすぎる / 暗すぎる状況をユーザー自身で調整できるようにすることで、月 1〜2 回の運営での疲労を減らす。OS の設定追従を既定値にすることで「設定を触る前から自然に見やすい」状態を担保しつつ、好みで固定したい人にも対応する。サークル単位ではなく **個人 preference** にした理由は、同じサークル内でも視覚的な好みは人それぞれ違うのが自然で、サークルブランディングは別途「結果カードの背景画像」「招待リンクの QR」で表現済みのため。

#### 3.1.4 設定項目とその意味

| 項目 | 入力形式 | 推奨 / 既定値 | 業務上の意味 |
| --- | --- | --- | --- |
| テーマ | 3 択ボタン（太陽 / 月 / モニタ） | OS の設定に従う | アプリ全体の色調 |

選択肢の意味:

| 選択肢 | アイコン | 動作 |
| --- | --- | --- |
| ライトモード | 太陽 | 常に明るい配色で表示 |
| ダークモード | 月 | 常に暗い配色で表示（深ネイビー基調） |
| OS の設定に従う | モニタ | 端末の OS 設定（昼 = ライト / 夜 = ダーク）に自動追従。OS 側で切り替えるとアプリも即連動 |

#### 3.1.5 注意点・制約

- 設定は **端末（ブラウザ）ごとに別** に保存される。スマホで「ダーク」を選んでも、別の PC では「OS の設定に従う」のまま（同期されない）
- ブラウザのキャッシュ / サイトデータをクリアすると設定がリセットされ、「OS の設定に従う」に戻る
- ブラウザのプライベートモード（シークレットウィンドウ）では、ウィンドウを閉じると設定が失われる
- アカウントを切り替えても（サインアウト → 別アカウントでサインイン）、端末の設定はそのまま引き継がれる
- 「OS の設定に従う」中は OS 側の昼夜切替に即時追従するが、明示的に「ライト」「ダーク」を選んだ後は OS を切り替えても影響しない（明示選択を尊重する）

### 3.2 表示連動（QR コード / 優勝者バナー / モバイル status bar）

#### 3.2.1 何ができる機能か

- テーマ切替に応じて、アプリ内の **以下の表示要素が自動で読みやすさ調整** される:
  - **QR コード**（招待リンクの QR / 観戦 URL の QR）— 背景にカード色を合わせ、ダークモードでも読み取りやすい配色になる
  - **優勝者バナー** — トーナメント終了時に表示される金色グラデーションのバナーが、ダークモードでも視認しやすい配色に切り替わる
  - **モバイルブラウザの status bar / PWA スプラッシュ** — Android Chrome のアドレスバー色や iOS Safari の status bar 色が、OS 設定に応じて自動で明 / 暗に切り替わる（端末側の現在の OS 設定が基準）
- 配色は固定の対応関係で動作するため、運営者・参加者の操作は不要

#### 3.2.2 誰が・いつ使うか

- 全ユーザーが、テーマ切替後・OS の昼夜モード変更後に体感する
- 招待リンク QR を見せるとき、トーナメント終了の優勝演出を見せるとき

#### 3.2.3 なぜこの機能が必要か（Why）

テーマ切替が「文字色だけ反転」のような単純な仕組みだと、QR コードや装飾要素の読みやすさが崩れて実用性が落ちる。**「テーマを切り替えても、サークル運営に必要な視認性が保たれる」** 状態を担保するため、視認性に直結する要素は個別に配色を用意している。QR コードはカメラ読取に直接効くため、特に重要。

#### 3.2.4 設定項目とその意味

該当なし。テーマ選択に **自動連動** するため、個別の調整項目はない。

#### 3.2.5 注意点・制約

- 結果カードの **共有画像（PNG）** はテーマ切替の対象外。シェア先（LINE / X 等）の閲覧者環境に依存しないよう、別途「ライト / ダーク」のテキストテーマ切替が **サークル単位** で用意されている（[02-circles-and-membership.spec.md](02-circles-and-membership.spec.md) と [08-season-stats.spec.md](08-season-stats.spec.md) を参照）
- アプリ起動直後に **ちらつき（FOUC）が起きない** よう、ブラウザに保存された設定はページ描画前に読み込まれる仕組みになっている。ただし、ごく古い端末・ブラウザでは数フレーム遅れる場合がある（OS の組み込みブラウザ等）
- 観戦モードの公開 URL（[10-spectate-mode.spec.md](10-spectate-mode.spec.md)）でも同じ仕組みでテーマが効く。観戦者の端末側 OS 設定に追従する

### 3.3 初回起動時の自動判定

#### 3.3.1 何ができる機能か

- まだ設定をしていない端末でアプリを開いた場合、**自動的に OS の設定に追従** する
- OS が「ダークモード」であればアプリもダークパレットで起動、ライトモードであればライトパレットで起動
- 明示的に「ライト」「ダーク」を選ぶまでは、OS の昼夜切替に自動追従し続ける

#### 3.3.2 誰が・いつ使うか

- 新規ユーザー全員が、初めてアプリを開いたとき
- 端末のキャッシュをクリアした後のユーザー
- プライベートモードのウィンドウを開いた人

#### 3.3.3 なぜこの機能が必要か（Why）

「設定を変えないと使いにくい」状態を最初の体験で起こさないため。OS 側でダークを使っている人にライトを押し付けるのは初回体験として悪く、また OS の昼夜自動切替を使っている人にとって「アプリだけライト固定」だと夜間に眩しい。OS 設定の追従を既定にすることで、初回起動時から自然な見え方を実現する。

#### 3.3.4 設定項目とその意味

該当なし。判定は自動。

#### 3.3.5 注意点・制約

- ごく古い OS / ブラウザ（OS のテーマ設定 API に対応していないもの）では、常にライトモードで起動する（フォールバック）
- 自動判定の結果が気に入らない場合は、[/settings](/settings) で明示的に切り替えれば以降は明示選択が優先される

## 4. 権限・認可

### 4.1 ロール別操作マトリクス

テーマ設定は **個人 preference** であり、サークルのロールにかかわらず全ユーザーが同じ操作権限を持つ。ロール別の制限ではなく、**サインイン方式の有無**でアクセス可否が決まる:

| 操作 | オーナー | 運営担当者 | 一般メンバー | ゲスト（匿名） | サインアウト（未認証） |
| --- | --- | --- | --- | --- | --- |
| [/settings](/settings) でテーマを明示切替 | ○ | ○ | ○ | ○ | × |
| OS 設定追従でテーマが自動切替される | ○ | ○ | ○ | ○ | ○ |
| 端末ごとに別の設定を持つ | ○ | ○ | ○ | ○ | ○ |
| 他のメンバーのテーマ設定を変更する | × | × | × | × | × |

凡例: ○ 可 / × 不可

### 4.2 ロール定義（spec 内の文脈で）

- **オーナー / 運営担当者 / 一般メンバー**: サインイン済みユーザー。テーマ設定の操作権限は同等
- **ゲスト（匿名）**: ゲスト匿名でもサインイン中なので [/settings](/settings) に到達でき、テーマを明示切替できる
- **サインアウト（未認証）**: [/settings](/settings) には到達できないが、OS 設定に自動追従する経路は機能する

### 4.3 補足

- 他人のテーマ設定を変える経路は存在しない（個人の端末ローカルに保存されるため、サーバ経由で他人の設定を上書きできる仕組み自体がない）
- サークルオーナーであっても、サークルメンバーにテーマを強制することはできない
- 同じアカウントで複数端末を使っているユーザーの設定は **端末ごとに独立** する（同期されない）

## 5. 非機能要件（業務観点）

### 5.1 パフォーマンス（体感）

- テーマ切替のクリックから画面全体の色が切り替わるまで **1 秒以内**（ほぼ瞬時）
- アプリ起動時の初回テーマ判定によるちらつきは **発生しない**（ページ描画前に判定済み）
- OS の昼夜モード変更時、アプリ画面を開いている間は **数秒以内に追従**する

### 5.2 セキュリティ（運用方針）

- テーマ設定は **個人の端末ブラウザにのみ保存** され、サーバ（クラウド上のデータベース）には一切送信・保存されない
- アカウント情報・参加履歴・サークル設定とは完全に独立しているため、他のメンバーから設定値が見られることはない
- 端末を共有して使う場合（家族 PC など）は、ブラウザのプロファイル分離やプライベートモードを使うことを推奨

### 5.3 使いやすさ / アクセシビリティ

- 3 つの選択肢にはアイコンと音声案内ラベル（「ライトモード」「ダークモード」「OS の設定に従う」）が両方付き、視覚 / 聴覚どちらの読み取り方でも区別できる
- 選択肢はキーボード（タブキー + 矢印キー）でも操作できる
- 現在選択中の項目は背景色のハイライトで示される
- ダークパレットは長時間視認しても目が疲れにくい暖色シルバー基調にしてある
- ライト / ダークの両方で **文字と背景のコントラスト** は一般的なアクセシビリティ基準を満たす配色を選定（暗い背景に明るい文字 / 明るい背景に暗い文字の十分なコントラスト比を確保）

### 5.4 信頼性 / エラー時の挙動

- ブラウザのサイトデータ保存が無効化されている / 容量超過などで保存できない場合、設定変更はその場では反映されるが次回起動時には「OS の設定に従う」に戻る（エラーで停止せず、安全側にフォールバック）
- ブラウザが OS のダークモード判定機能に未対応の場合は、常にライトモードで起動する
- 設定値が壊れている / 想定外の値が保存されている場合は、自動的に「OS の設定に従う」にフォールバックする

### 5.5 保守性 / 運用負担

- 運営者がメンバーのテーマ設定を管理する必要はない（個人 preference のため）
- アプリの配色を変更したい場合は、開発者の作業（配色定義の更新）が必要。サークル運営者・一般メンバーが直接配色をカスタマイズすることはできない
- テーマ追加（例: セピア / ハイコントラスト）には開発者の対応が必要。本仕様書時点では 3 種類のみ

### 5.6 互換性

- 動作対象: モダン Web ブラウザ（Chrome / Safari / Firefox / Edge の最新数バージョン）
- スマートフォン（Android Chrome / iOS Safari）・タブレット・PC で同じように動作
- 既存ユーザーには影響なし（初回起動時に「OS の設定に従う」が自動適用される）
- PWA（ホーム画面追加）で起動した場合も同じ仕組みで動作する

### 5.7 運用 / 観測性

- テーマ切替の操作は内部の操作記録には残らない（個人の見え方の好みのため、トレースする必要がないと判断）
- 設定の保存 / 読込に失敗した場合は内部の警告ログに記録される（運営者は普段は意識する必要なし）
- ユーザーから「色がおかしい」と問合せがあった場合は、ブラウザのキャッシュクリア → 再読込で OS 設定追従に戻ることを案内する

## 6. 既知の制約・未対応事項

- **端末横断同期は未対応**: 同じアカウントで複数端末を使っていても、設定は端末ごとに独立。スマホで「ダーク」を選んでも別 PC では再設定が必要
- **追加テーマ（セピア / ハイコントラスト / カスタム配色）は未提供**: 用意しているのは「ライト / ダーク / OS 設定追従」の 3 種類のみ
- **サークル単位のテーマ強制は未提供**: オーナーが「このサークルではダークを使ってほしい」と強制する仕組みはない（個人 preference のため）
- **結果カードの共有画像（PNG）にはテーマ切替が効かない**: シェア先環境に依存しないよう、結果カードは別途サークル単位で「ライト / ダーク」のテキストテーマを切替える経路を持つ（[02-circles-and-membership.spec.md](02-circles-and-membership.spec.md) / [08-season-stats.spec.md](08-season-stats.spec.md) 参照）
- **時刻ベースの自動切替（日没でダーク等）は OS 任せ**: アプリ独自の時刻スケジューラは持たない。OS 側の昼夜自動切替を活かしたいユーザーは「OS の設定に従う」を選ぶ
- **ゲスト匿名は明示切替は可能だが、サインアウト直後に履歴がリセットされる**: 匿名アカウントは自動削除フローと連動するため、サインアウト後にブラウザ側の設定が一部消える場合がある
- **ライトモードのみのページが残っている可能性**: アプリ全体でダークパレットを整備しているが、一部の細かい色（情報バナーの sky 色など）は意味的に固定で、ダークモードでも同じ色が使われる
