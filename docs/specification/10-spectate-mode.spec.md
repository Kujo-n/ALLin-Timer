# 観戦モード（公開 URL）業務仕様書

## 1. 概要

トーナメント単位で運営者が **明示的に ON にしたときだけ**、サインインなしで誰でも閲覧できる **観戦専用 URL（[/spectate/[tid]](/spectate/%5Btid%5D)）** を提供する機能。会場の予備モニタへの投影と、会場到着前の遅刻参加者の状況確認を、ログイン操作・チャット問い合わせなしに完結させる。観戦ページではタイマー・ブラインド・残人数・席表・レイトレジスト受付状況だけが読み取り専用で表示され、操作ボタンや個人連絡先は一切出ない。運営者が OFF に切り替えると、観戦中の画面は **「観戦が終了しました」** に自動遷移する。サークルへの参加そのものは従来通り受付 URL（[/join/[tid]](/join/%5Btid%5D)）で行う。主に運営者ダッシュボード（[/tournaments/[tid]](/tournaments/%5Btid%5D)）と新規追加された観戦ページ（[/spectate/[tid]](/spectate/%5Btid%5D)）で使う。

## 2. 想定利用シーン

### 2.1 ペルソナ

- **会場の予備モニタを操作する運営者**: 本体機（PC）はダッシュボード操作用、別画面（iPad / 別 PC / プロジェクタ）はタイマー投影用と分けたい人
- **遅刻参加者**: 開始時刻に間に合わず会場に向かう途中で、現在のレベル・残人数・レイトレジスト可否を急いで知りたい人
- **会場外の関係者**: 家族 / サークル仲間 / 配信視聴者で、サインインしていなくても進行を眺めたい人
- **opt-in を判断する運営者**: 観戦モードを使うか毎回判断する運営者。誤公開を防ぎたい

### 2.2 シナリオ

#### 2.2.1 平常系: 会場の予備モニタを観戦 URL で投影

運営担当者 A さんが、本体機の [/tournaments/[tid]](/tournaments/%5Btid%5D) を運営操作用に開いている → 観戦モードカードの「ON にする」ボタンを押す → 確認ダイアログで「URL を知る人は誰でも閲覧できます」と告知される → 「ON にする」を確定 → 画面に観戦 URL と QR コードが表示される → 予備モニタ（iPad）で URL を開く → サインイン操作なしでタイマー・席表・残人数が即座に表示される → 会場全員から見える状態になる。

#### 2.2.2 平常系: 遅刻参加者が会場へ向かう途中で状況確認

参加者 B さんが開始時刻に遅刻し、電車で会場へ移動中 → 運営者から共有された観戦 URL を LINE で受け取る → URL を開く（ログイン不要）→ 画面上部に「Lv 2 まで受付中（あと 8 分）」のレイトレジスト banner が表示される → B さんは「間に合う」と判断して急ぐ → 残人数・自分の知人の名前を席表で確認 → 会場到着後、別途 [/join/[tid]](/join/%5Btid%5D) で正規参加。

#### 2.2.3 失敗系: 観戦モードを OFF に切り替えた直後の挙動

観戦中の C さんがブラウザで [/spectate/[tid]](/spectate/%5Btid%5D) を開いている → 運営者がトーナメントを終了処理にした瞬間に、観戦モードが **自動で OFF に倒れる**（運営者が手動でスイッチを操作する必要なし） → C さんの画面が **「観戦が終了しました」** に自動遷移する → 白画面 / 不明エラーにはならない → C さんはトーナメント終了を察知し、ブラウザを閉じる。

#### 2.2.4 失敗系: レイトレジスト締切後の遅刻

参加者 D さんが大幅に遅刻し、観戦 URL を開いた時点で **レイトレジスト締切レベル超過** → banner が「受付終了」表示 → D さんは「今日は観戦のみ」と判断する → そのまま会場へ向かい、終了まで観戦モードでタイマーと席表を眺める。

#### 2.2.5 運用系: 観戦中の通信瞬断

iPad で観戦投影中、会場の Wi-Fi が瞬断 → 観戦ページもタイマー進行を最後の同期時点で表示し続ける（数分の stale 許容）→ 通信回復後は最新状態に自動同期される（運営者ダッシュボードのオフライン耐性と同じ仕組み）。

#### 2.2.6 運用系: 一般メンバーが誤って観戦 URL を共有しようとする

一般メンバー E さんが「他のメンバーにも見せたい」と運営者ダッシュボードを開こうとする → 一般メンバーには **観戦モードカードが表示されない**（toggle UI が見えない）→ E さんは運営者に依頼する形になる → 観戦 URL の発行は必ず owner / 運営担当者を経由する設計が保たれる。

## 3. 機能要件

### 3.1 観戦モードの ON/OFF 切替（ダッシュボード）

#### 3.1.1 何ができる機能か

- 運営者ダッシュボード [/tournaments/[tid]](/tournaments/%5Btid%5D) に **「観戦モード」カード** が表示される（owner / 運営担当者のみ）
- カード内のスイッチを ON にすると、確認ダイアログ「観戦モードを ON にすると、URL を知る人は誰でも閲覧できます」が出る
- 「ON にする」確定後、観戦 URL（フル URL）と QR コードがカード内に表示される
- OFF に切り替えると、URL は同じだが **観戦ページは「観戦が終了しました」表示に自動遷移** する（観戦中の閲覧者にも即時反映）
- 切替後の状態（ON / OFF）は他の運営者の画面にも自動反映される
- **トーナメントを終了状態に進めると、観戦モードは自動的に OFF に倒れる**（運営者が手動で OFF にする必要がない）。終了処理と観戦 OFF はまとめて確定されるため、終了したのに「観戦公開中」のまま放置される事故が起きない。必要であれば終了後に運営者が同じカードから再度 ON にできる

#### 3.1.2 誰が・いつ使うか

- owner / 運営担当者が、会場の予備モニタ投影 / 遅刻参加者への状況共有を判断したとき
- 終了後 / 開催前は OFF にして公開状態を残さないようにしたい運営者

#### 3.1.3 なぜこの機能が必要か（Why）

会場の予備モニタを毎回別アカウントでサインインさせるのは煩雑で、参加者からの「もう始まってる？レイトレジスト間に合う？」という都度問い合わせも運営の負担になる。観戦モードを **トーナメント単位の opt-in トグル** にすることで、必要なタイミングだけ公開して摩擦なしに共有でき、終了後は OFF にして公開状態を残さない運用に倒せる。「URL を知る人は誰でも閲覧できる」確認ダイアログを必須にすることで、誤公開を防ぐ。

#### 3.1.4 設定項目とその意味

| 項目 | 入力形式 | 推奨 / 既定値 | 業務上の意味 |
| --- | --- | --- | --- |
| 観戦モード ON/OFF | スイッチ | OFF（既定）| トーナメント単位の公開状態 |

#### 3.1.5 注意点・制約

- ON 切替時の確認ダイアログは **省略不可**（誤公開防止のため、スイッチ単独では切り替わらない設計）
- 一般メンバー / ゲスト匿名には観戦モードカード自体が表示されない（toggle 経由の誤操作不可）
- **トーナメント終了時に観戦モードは自動 OFF に倒れる**ため、「終了したのに観戦公開中のまま」状態は起きない。ただし運営者が終了後にあえて再度 ON に戻すことは可能（リプレイ振り返り用途など）
- スイッチ切替後の反映は 1 〜 2 秒以内（他端末の画面にも自動同期）

### 3.2 観戦 URL の表示・コピー・QR コード

#### 3.2.1 何ができる機能か

- 観戦モードを ON にすると、ダッシュボードのカード内に観戦 URL（`https://.../spectate/<tid>` のフル URL）が表示される
- 「URL をコピー」ボタンでクリップボードに 1 タップでコピーできる（コピー後 toast で完了通知）
- QR コードも同時に表示され、対面で来訪者にスマホでスキャンしてもらうだけで観戦ページに到達できる
- LINE / X 等のチャットへ URL 貼付、会場での QR スキャン、両方の共有導線を 1 か所で完結する

#### 3.2.2 誰が・いつ使うか

- owner / 運営担当者が、観戦モード ON 直後に共有先（チャット / 対面 QR）を判断するとき
- 予備モニタ・遅刻参加者・家族など、それぞれの相手に合わせた共有手段を選びたいとき

#### 3.2.3 なぜこの機能が必要か（Why）

「URL を手で打ってもらう」「画面を撮影して送る」のような手動運用は摩擦が大きく、観戦モードの初動価値（即座に共有できる）が削がれる。コピーと QR の両方をリリース時点で必須にすることで、運営者の利用判断に「あとで導線が増えるか」の不確実性を残さない。

#### 3.2.4 設定項目とその意味

該当なし（自動表示）。表示される URL は固定（tid 直貼り）で、運営者が短縮版や別 URL に置換することはできない。

#### 3.2.5 注意点・制約

- URL 文字列自体が秘密性の核なので、流出前提で運用する（チャット送信履歴や QR の写真撮影で漏れる可能性）
- ON / OFF を頻繁に切り替えても URL は変わらない（同じ tid から派生）
- 短命 token / revocable code の発行は本仕様書時点では非対応（既知の制約として後述）

### 3.3 観戦ページ（[/spectate/[tid]](/spectate/%5Btid%5D)）の表示

#### 3.3.1 何ができる機能か

- 観戦モードが ON になっているトーナメントについて、サインインなしで以下の情報が読み取り専用で表示される
  - **タイマー**（現在のレベル名・残り時間 MM:SS、サーバ時刻基準で同期）
  - **ブラインド**（現レベルの SB / BB / アンティ）
  - **残人数**（バスト前の参加者数）
  - **席表**（卓ごとの参加者表示名 / Table 名 / 色 / プレイングディーラー印）
  - **レイトレジスト受付状況 banner**（後述）
- 操作ボタン（一時停止 / 次レベル / バスト / 席移動など）は一切表示されない
- 全画面表示にすれば、会場の大画面投影に使える
- タイマーは運営者ダッシュボードと同じく自動更新で同期される

#### 3.3.2 誰が・いつ使うか

- 観戦 URL を運営者から受け取った人が、ログイン不要で進行を確認したいとき
- 会場の予備モニタにブラウザを開いて、ダッシュボードと別画面で投影したいとき

#### 3.3.3 なぜこの機能が必要か（Why）

会場の予備モニタを別アカウントでサインインさせる手間を省き、家族 / 配信視聴者 / 遅刻参加者にも同じ進行を見せられる。**観戦専用ページに操作系を一切置かないことで、誤操作・誤クリック・運営権限の漏洩を防ぐ**。

#### 3.3.4 設定項目とその意味

該当なし（読み取り専用）。表示の有無は運営者の観戦モード ON/OFF に従う。

#### 3.3.5 注意点・制約

- 観戦ページから「参加する」導線は提供されない（受付フローは [/join/[tid]](/join/%5Btid%5D) に集約）
- 表示名は参加者本人が設定したものがそのまま見える（観戦経路用の別名 / マスクは未提供）
- チップ量・賞金構造などは表示されない（アプリ自体がこれらを扱っていないため）
- 観戦モードが OFF に切り替わった瞬間に「観戦が終了しました」表示に自動遷移する（後述）

### 3.4 レイトレジスト受付状況 banner

#### 3.4.1 何ができる機能か

- 観戦ページ上部に **レイトレジスト banner** が常時表示される
- 現在のレベルがレイトレジスト締切レベル以下のとき: **「Lv X まで受付中」**（残時間も合わせて表示される場合あり）
- 現在のレベルが締切レベルを超えているとき: **「受付終了」**
- ブラインドアップに合わせて自動で更新される

#### 3.4.2 誰が・いつ使うか

- 遅刻参加者が会場へ移動中に「間に合うか」を判断したいとき
- 会場の予備モニタで「今レイトレジスト可能か」を全員に伝えたいとき

#### 3.4.3 なぜこの機能が必要か（Why）

「もう始まってる？レイトレジスト間に合う？」というチャット問い合わせは、運営者が画面を確認してから返答する必要があり、当日の進行中には対応しきれない。banner として明示的に出すことで、観戦者本人が秒で判断できる。

#### 3.4.4 設定項目とその意味

該当なし（自動表示）。レイトレジスト締切レベルの値はトーナメント作成時のストラクチャ（[03-structures-and-templates.spec.md](03-structures-and-templates.spec.md)）で決定される。

#### 3.4.5 注意点・制約

- banner の正確性はストラクチャ側のレイトレジスト締切設定が前提。運営者が締切設定を間違えると banner も誤った内容を表示する
- レイトレジスト締切後の参加可否について、観戦ページから直接受付に進むことはできない

### 3.5 トーナメント一覧の「観戦公開中」バッジ

#### 3.5.1 何ができる機能か

- [/tournaments](/tournaments) のトーナメントカードに、観戦モードが ON のトーナメントには **「観戦公開中」バッジ** が表示される
- バッジは owner / 運営担当者・一般メンバーの全員に見える
- 一覧画面でどのトーナメントが今公開中かを 1 目で判別できる

#### 3.5.2 誰が・いつ使うか

- 運営担当者が、誤って ON のまま放置していないか定期的に確認したいとき
- 終了後に OFF 忘れがないか一覧で確認したいとき

#### 3.5.3 なぜこの機能が必要か（Why）

観戦モード ON の状態は **トーナメント単位の opt-in** だが、ダッシュボードを開かないと公開状態が分からない。「終了したのに ON のまま」「次回開催時に ON が引き継がれた」のような誤公開放置リスクを、一覧画面で即座に検知できるようにするため。

#### 3.5.4 設定項目とその意味

該当なし（自動表示）。

#### 3.5.5 注意点・制約

- バッジは現在のサークルのトーナメントに限定される（別サークルの観戦モード状態は見えない）
- バッジから直接 OFF に切り替える操作は提供しない（ダッシュボードに遷移して操作する）

### 3.6 観戦中に OFF に切り替わったときの自動遷移

#### 3.6.1 何ができる機能か

- 観戦中の画面で、運営者が観戦モードを OFF に切り替えた瞬間（または読み取り権限が失われた瞬間）に **「観戦が終了しました」** という分かりやすい画面に自動遷移する
- 白画面 / 不明エラー / 古いタイマー表示が残ったまま、にはならない
- 観戦者は「自分のネットが切れたのか / トーナメントが終わったのか」を即座に識別できる

#### 3.6.2 誰が・いつ使うか

- 観戦中の閲覧者全員（投影端末・遅刻参加者・家族など）
- 運営者が終了処理の一環として OFF に切り替えたとき

#### 3.6.3 なぜこの機能が必要か（Why）

トグル切替時に観戦画面が white screen になると、観戦者が「何が起きたか分からない」混乱状態に陥り、運営者へ問い合わせが集中する。明示的な「観戦が終了しました」表示にすることで、観戦者の混乱を防ぎ、運営の負担も減る。

#### 3.6.4 設定項目とその意味

該当なし（自動処理）。

#### 3.6.5 注意点・制約

- ネットワーク切断による表示不能と、運営者の意図的な OFF を内部で同じく扱う（読み取り権限喪失で画面遷移）。ネットが回復しても OFF のままなら継続表示
- 「観戦が終了しました」画面からブラウザのリロードで観戦ページに戻ろうとしても、OFF 状態なら同じ画面が再表示される

### 3.7 通信不安定時の継続表示（観戦モードのオフライン耐性）

#### 3.7.1 何ができる機能か

- 観戦モードでも、運営者ダッシュボード / 参加者向け表示と同じく、一時的な通信障害でタイマーと席表が完全には消えない
- 観戦ページ自体のキャッシュにより、会場で Wi-Fi が瞬断しても **数分以内の stale 状態** で表示が維持される
- 通信回復後は最新状態に自動同期される
- 詳細仕様（タイマーのオフライン耐性）は [09-pwa-app-shell.spec.md](09-pwa-app-shell.spec.md) と [06-timer-and-blinds.spec.md](06-timer-and-blinds.spec.md) を参照

#### 3.7.2 誰が・いつ使うか

- 会場の予備モニタが Wi-Fi 不安定な席にあるとき
- 遅刻参加者がトンネル隣接区間など電波が弱い場所を通過するとき

#### 3.7.3 なぜこの機能が必要か（Why）

観戦モードの主用途（予備モニタ投影 / 移動中確認）は、必ずしも安定した通信環境ではない。瞬断のたびに白画面になると観戦の信頼性が下がり、結果として運営者が観戦モードを使わなくなる。

#### 3.7.4 設定項目とその意味

該当なし（自動処理）。

#### 3.7.5 注意点・制約

- stale 許容範囲は **数分以内**。長期間（数時間）放置した観戦タブは古いブラインドを表示する可能性があるため、タイマー進行に合わせて適宜リロード推奨
- 完全オフライン環境（モバイル回線完全死）では観戦ページも到達不可
- 詳細は [06-timer-and-blinds.spec.md](06-timer-and-blinds.spec.md) 3.9 節 と [09-pwa-app-shell.spec.md](09-pwa-app-shell.spec.md) 3.3 節を参照

### 4.1 ロール別操作マトリクス

| 操作 | オーナー | 運営担当者 | 一般メンバー | ゲスト（匿名） | 未サインイン（観戦のみ）|
| --- | --- | --- | --- | --- | --- |
| 観戦モード ON/OFF の切替 | ○ | ○ | × | × | × |
| 観戦モードカード（ダッシュボード）の表示 | ○ | ○ | × | × | × |
| 観戦 URL の表示・コピー・QR の参照 | ○ | ○ | × | × | × |
| トーナメント一覧の「観戦公開中」バッジ閲覧 | ○ | ○ | ○ | × | × |
| 観戦ページ [/spectate/[tid]](/spectate/%5Btid%5D) の閲覧（ON のとき）| ○ | ○ | ○ | ○ | ○ |
| 観戦ページから参加（受付）に進む | × | × | × | × | × |
| 観戦ページからの操作（一時停止 / バスト / 席移動など）| × | × | × | × | × |
| OFF 切替後の「観戦が終了しました」表示の閲覧 | ○ | ○ | ○ | ○ | ○ |

凡例: ○ 可 / × 不可

「未サインイン（観戦のみ）」列は、本 spec で観戦経路の主役となる **アプリにサインインしていない閲覧者**（家族 / 配信視聴者 / 会場到着前の参加者など）を指す。

### 4.2 ロール定義（spec 内の文脈で）

- **オーナー**: 観戦モードカードの toggle 操作と URL 共有が可能。一般的なオーナー権限の延長
- **運営担当者**: オーナーと同じく観戦モードを切替・共有できる。誤公開時の責任範囲を運営側に集約する設計
- **一般メンバー**: 観戦 URL を受け取れば閲覧できるが、自分で公開する権限はない
- **ゲスト（匿名）**: サークル所属していなくても観戦 URL を開けば閲覧できる
- **未サインイン（観戦のみ）**: アプリにサインインしていない閲覧者。観戦 URL を直接開けば、サインイン操作なしで閲覧できる

### 4.3 補足

- **観戦 URL を知っている人 = 閲覧可能** という設計のため、URL 流出は閲覧範囲の拡大を意味する。秘密 URL の運用ルール（誰に共有するか）は運営者の判断
- 観戦経路は **読み取り専用** が厳格に保たれる。仕組み上、操作系の API も観戦者には届かない設計
- 観戦モード切替を一般メンバーに開放しない設計は、誤公開リスクの一元管理（責任範囲を運営層に集約）が目的

## 5. 非機能要件（業務観点）

### 5.1 パフォーマンス（体感）

- 観戦モードの ON/OFF 切替は 1〜2 秒以内に他端末・観戦中の画面に反映
- 観戦ページの初回読み込みは数秒以内（PWA キャッシュにより 2 回目以降は短縮）
- タイマーの自動更新は運営者ダッシュボードと同じく 1 秒間隔
- 20 人前後・6 卓以下のサークル運用では遅延の体感はない

### 5.2 セキュリティ（運用方針）

- 観戦 URL の文字列は **推測困難な ID（約 117 ビット相当）** を使用しているため、URL を知らない第三者が当てずっぽうでアクセスすることはできない
- ON 切替時に **「URL を知る人は誰でも閲覧できます」** の確認ダイアログを必須化（誤公開防止）
- 観戦経路は読み取り専用で、観戦者から運営操作・データ書込は一切できない
- 表示名・席表・卓ラベルは観戦時にも見えるが、メールアドレスや個人連絡先は表示されない
- トーナメントの一覧 / 招待コードに観戦経路から到達することはできない（公開対象は当該トーナメントのみ）
- 観戦 URL が漏洩した場合、第三者が観戦すること自体は防げないが、**観戦者は読み取り以上の操作はできない**

### 5.3 使いやすさ / アクセシビリティ

- 観戦ページはサインイン不要のため、URL を踏むだけで誰でも到達できる
- スマホ・タブレット・PC・大画面投影のすべてで同じ表示が出る
- レイトレジスト banner は遠見対応の大きな文字で表示
- 「観戦が終了しました」表示は、観戦者が混乱しないよう明確な日本語で 1 行表示
- QR コードは対面の高齢メンバーや視力の弱いメンバーにも便利な共有手段
- 操作ボタンが一切ないため、誤タップで意図しない操作が発生する心配がない

### 5.4 信頼性 / エラー時の挙動

- 観戦ページで通信切断時はタイマー / 席表の最終同期時刻まで表示が維持される（数分の stale 許容）
- 運営者の OFF 切替を観戦者の画面で取りこぼさず、「観戦が終了しました」へ確実に遷移する
- 同時に複数の運営者が ON / OFF を切り替えた場合、後勝ちで反映される（観戦者の画面も最終状態に追従）
- トーナメント自体が削除された場合、観戦ページは「観戦が終了しました」画面に自動遷移する

### 5.5 保守性 / 運用負担

- 観戦モードはトーナメント単位の独立フラグなので、複数開催を並行運用しても干渉しない
- ON / OFF の状態は永続化されるため、誤って OFF 忘れがあっても次回ダッシュボードで一覧バッジから検知できる
- 共有手段（URL / QR / コピー button）が同じカードに集約されているため、運営者の運用知識は単一画面で完結する
- 公開対象を絞り込む / 短命 token を発行する高度な制御は将来 PRD で扱う（現状は tid 直貼り）

### 5.6 互換性

- 動作対象: モダン Web ブラウザ（Chrome / Safari / Firefox / Edge の最新数バージョン）
- スマホ・タブレット・PC・会場プロジェクタの主要端末で同じように表示
- PWA 化対応（[09-pwa-app-shell.spec.md](09-pwa-app-shell.spec.md)）と整合的に動作。観戦ページもオフラインキャッシュの対象
- 過去の観戦モード未対応のトーナメントは、自動的に「観戦モード OFF（既定）」状態として扱われ、移行作業は不要

### 5.7 運用 / 観測性

- 観戦モード ON / OFF の切替は内部の操作記録に残る（誰がいつ切り替えたか）
- 観戦ページへのアクセス数は本仕様書時点では集計していない（将来拡張余地）
- 観戦中に異常が起きた場合、運営者は観戦モードを OFF → ON で再生成 / または対象トーナメントの状態を再読み込みすることで復旧できる
- 障害時はダッシュボードを再読み込みすれば現状確認できる

## 6. 既知の制約・未対応事項

- **観戦 URL は tid 直貼り**: 短命の revocable token は未実装。URL が広範に拡散した場合の制御はトグル OFF のみ（同じ tid を再公開すると同じ URL になる）
- **チップ量 / 賞金構造の表示なし**: アプリ自体がこれらを扱わない設計
- **観戦ページからの参加導線なし**: 受付は [/join/[tid]](/join/%5Btid%5D) に集約。観戦 → 受付の遷移はリンクで案内せず、別経路で誘導
- **uid（内部 ID）が席表に隠れる形で見える可能性**: 表示名は隠せないため、観戦者には全参加者の表示名が見える。匿名性が必要な運営は対象外
- **観戦者向けインタラクションなし**: チャット / リアクション / 拍手などの双方向機能は未提供（read-only に徹する）
- **特定メンバーのみへの限定公開なし**: 公開は「誰でも見られる / 完全に閉じる」の二択
- **観戦アクセス数の集計なし**: 公開頻度・効果測定は運営者の手動ヒアリング
- **観戦中の自動 OFF（タイムアウト）なし**: 観戦中の経過時間で自動 OFF されることはない。**ただしトーナメントを終了状態に進めた瞬間には自動 OFF に倒れる**（運営者の手動操作なしで公開停止）。長期 ON 放置の検知は一覧バッジで補う
