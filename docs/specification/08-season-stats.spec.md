# シーズン戦績 業務仕様書

## 1. 概要

サークル単位で **「シーズン」と呼ばれる任意の期間** を設けて、その期間内のトーナメント参加履歴を累計集計する機能。各メンバーの **参加回数・優勝回数・ファイナルテーブル（FT）進出回数・累計ポイント** を自動的に集計し、ランキング画面で確認できる。シーズン区切りは **運営者の手動切替** で行い、過去シーズンは **履歴に snapshot** されて閲覧可能になる。シーズン首位は画像カード PNG としてダウンロードでき、サークル LINE / X に貼って盛り上がり素材にできる。主に [/groups/[gid]/season](/groups/%5Bgid%5D/season) で確認する。

## 2. 想定利用シーン

### 2.1 ペルソナ

- **継続支援を意識する運営者**: 月 1〜2 回開催のサークルで、参加者の継続意欲を維持したい人
- **競技志向の参加者**: 「自分の今シーズンの成績を見たい」「他人と比較したい」と思う人
- **記録共有派**: シーズン首位カードを LINE / X に貼ってサークルを盛り上げたい人

### 2.2 シナリオ

#### 2.2.1 平常系: トーナメント終了とシーズン戦績の自動加算

トーナメントが終了 → 各参加者の参加回数 +1、最終順位に応じてポイントが加算 → 1 位の人は優勝回数 +1、9 位以内なら FT 回数 +1 → ランキング画面でリアルタイムに反映される。

#### 2.2.2 平常系: シーズンランキングの確認

サイドバーから [/groups/[gid]/season](/groups/%5Bgid%5D/season) を開く → 現在シーズンの累計ポイント順で参加者がランキング表示される → 各列で参加・優勝・FT・累計ポイントが確認できる → シーズン開始日も画面上部に表示される。

#### 2.2.3 平常系: シーズン首位カードのダウンロード

[/groups/[gid]/season](/groups/%5Bgid%5D/season) の「画像保存」ボタンを押す → シーズン首位の PNG カードが生成され、ブラウザの保存ダイアログが出る → 保存して LINE のサークルグループに貼付。

#### 2.2.4 運用系: シーズン手動切替（四半期 / 半期に 1 回）

運営者が「今月で前期シーズン終了、来月から新シーズンを始めたい」と判断 → [/groups/[gid]](/groups/%5Bgid%5D) で「シーズンを開始する」ボタンを押す → 確認ダイアログで「現在の戦績を履歴に保存して、新シーズンを開始しますか？」と表示 → 「開始」を押すと、現シーズンの戦績が履歴に snapshot され、各メンバーの戦績がリセットされ、シーズン開始日が現在時刻に更新される。

#### 2.2.5 失敗系: 進行中のトーナメントがあるときのシーズン切替

運営者が「シーズンを開始する」ボタンを押す → 進行中（受付中・実行中・一時停止中）のトーナメントが 1 件以上存在する → エラーメッセージ「現在進行中のトーナメントがあります。先に終了させてください」が表示 → 運営者は進行中トーナメントを終了させてから再度切替操作を実行。

#### 2.2.6 運用系: 過去シーズンの履歴閲覧

運営者が「先月の首位は誰だったか」を確認したいとき、[/groups/[gid]/season](/groups/%5Bgid%5D/season) の履歴セクションで過去シーズンの snapshot を閲覧できる（履歴閲覧 UI は polish phase で拡充予定）。

## 3. 機能要件

### 3.1 シーズン戦績の自動集計

#### 3.1.1 何ができる機能か

- トーナメントが「終了」状態になると、各参加者のシーズン戦績が自動的に更新される
- 更新内容: **参加回数 +1**、最終順位に応じた **累計ポイント加算**、1 位なら **優勝回数 +1**、9 位以内なら **FT 進出回数 +1**
- 更新はまとめて確定される（途中で失敗した場合は何も変わらない）
- 同じトーナメントが複数回終了することはない設計（二重加算なし）

#### 3.1.2 誰が・いつ使うか

- 全メンバーのシーズン戦績は自動で更新される
- 運営者は「シーズン戦績を更新する」ボタンを押す必要なし

#### 3.1.3 なぜこの機能が必要か（Why）

参加者の継続意欲を維持するため、サークルでの自分の活動が「累計として見える」ことが重要。手動で集計せず自動で進む設計にすることで、運営者の負担なしに戦績が積み上がる。

#### 3.1.4 設定項目とその意味

該当なし（自動集計）。トーナメント終了時の参加人数で自動的にポイントが計算される。

#### 3.1.5 注意点・制約

- ゲスト匿名（uid なし）の参加者は集計対象外
- バストした人も「参加した」とカウントされる
- トーナメント終了後にバストを取り消す UI は提供していない（取り消した場合の戦績再計算もない）

### 3.2 ポイント計算式

#### 3.2.1 何ができる機能か

- ポイントは **「順位ベース × 参加人数係数」** で計算される
  - 順位 1 位: 10 / 2 位: 7 / 3 位: 5 / 4 位: 3 / 5〜9 位: 1 / 10 位以下: 0
  - 参加人数係数: √(参加人数 / 8)
  - 例: 6 人開催の 1 位 = 10 × √(6/8) ≈ 8.66pt、20 人開催の 1 位 = 10 × √(20/8) ≈ 15.81pt
- 小数 2 桁で保持（表示時の四捨五入は画面側）

#### 3.2.2 誰が・いつ使うか

- ポイントはアプリが自動算出するため、運営者・参加者は意識しない

#### 3.2.3 なぜこの機能が必要か（Why）

「6 人と 20 人で同じ 10pt では違和感がある」という運営者要望に対応するため、参加人数で重みをつける式を採用している。平方根スケールを使うことで、人数増による差が極端になりすぎないバランスを取っている。

#### 3.2.4 設定項目とその意味

| 項目 | 値 | 業務上の意味 |
| --- | --- | --- |
| 1 位 base ポイント | 10 | 最高順位の固定ベース |
| 2 位 base | 7 | 上位 3 位までの差を残す |
| 3 位 base | 5 | 同上 |
| 4 位 base | 3 | 4 位の小さなご褒美 |
| 5〜9 位 base | 1 | FT 進出最低ポイント |
| 10 位以下 | 0 | ポイントなし |
| 参加人数係数の基準値 | 8 名 | 1 卓フル運用を「係数 1.0」とする |
| FT しきい値 | 9 位以内 | NLH 9 人卓に揃えた基準 |

本仕様書時点では、これらの値は運営者カスタマイズ不可（アプリ全体で固定）。

#### 3.2.5 注意点・制約

- 計算式は固定（運営者から変更できない）
- 同点（同順位）処理は内部で決定論的に行われる
- 浮動小数点誤差は 2 桁丸めで防止

### 3.3 シーズンランキング画面

#### 3.3.1 何ができる機能か

- [/groups/[gid]/season](/groups/%5Bgid%5D/season) で、現在シーズンの戦績ランキングを表示
- 各メンバーの順位 / 表示名 / 参加回数 / 優勝回数 / FT 回数 / 累計ポイントを表で確認
- 累計ポイント降順で並び替え（同点時は内部順）
- シーズン開始日が画面上部に表示される
- 「画像保存」ボタンでシーズン首位カードをダウンロード（後述）

#### 3.3.2 誰が・いつ使うか

- サークルメンバー全員が、自分・他人の戦績を確認したいとき
- 運営者がシーズン振り返りを行いたいとき

#### 3.3.3 なぜこの機能が必要か（Why）

「先月の首位は誰だったか」「自分は何位くらいか」を可視化することで、参加者の継続意欲フックになる。サークルランキングが動的に見えることで、参加の動機が増える。

#### 3.3.4 設定項目とその意味

該当なし（読み取り専用）。

#### 3.3.5 注意点・制約

- サークルメンバー全員が閲覧可能
- 戦績がまだない（このシーズンでトーナメントを終えていない）状態では「戦績はまだありません」と表示

### 3.4 シーズンの開始（手動切替）

#### 3.4.1 何ができる機能か

- [/groups/[gid]](/groups/%5Bgid%5D) で「シーズンを開始する」ボタン（オーナー / 運営担当者のみ表示）
- 確認ダイアログで「現在の戦績を履歴に保存して、新シーズンを開始します」と告知
- 「開始」を押すと:
  1. 現在の戦績全件を履歴に snapshot
  2. シーズン開始日を現在時刻に更新
  3. 各メンバーの戦績を 0 にリセット
- まとめて確定されるため、途中で失敗したら何も変わらない

#### 3.4.2 誰が・いつ使うか

- サークルの運営者が、四半期 / 半期 / 年度の区切りで新シーズンを始めたいとき

#### 3.4.3 なぜこの機能が必要か（Why）

サークルごとに開催ペースが違うため、自動切替（毎月 1 日 / 4 月 1 日 など）よりも運営者の判断で柔軟に切替えられる方が運用に合う。過去シーズンを履歴として残すことで、「先月の首位」の参照も可能。

#### 3.4.4 設定項目とその意味

該当なし（ボタン操作 + 確認ダイアログ）。

#### 3.4.5 注意点・制約

- **進行中のトーナメント（受付中・実行中・一時停止中）が 1 件でもあるとシーズン切替不可**（エラーメッセージ）
- 進行中トーナメントの終了後にシーズン切替するのは、運営者が「先に終了 → シーズン切替」の順で操作する
- シーズン切替の取り消しはできない（履歴は残るが、戦績の戻しは不可）
- 一般メンバーには「シーズンを開始する」ボタンが表示されない

### 3.5 シーズン履歴

#### 3.5.1 何ができる機能か

- 過去シーズンの戦績スナップショットがサークル単位で保存される
- 各履歴には終了時刻と参加者の戦績エントリが含まれる
- 履歴は閲覧のみ可能（編集・削除はできない）
- サークルメンバー全員が閲覧可能

#### 3.5.2 誰が・いつ使うか

- 運営者・参加者が「先月の首位は誰だったか」を確認したいとき
- 過去シーズンの自分の成績を振り返りたいとき

#### 3.5.3 なぜこの機能が必要か（Why）

シーズンの区切りで戦績がリセットされるが、過去のシーズンの記録を完全に消すと「あのシーズンの首位はあの人だった」という思い出が失われる。履歴として保存することで、長期的な記録と現シーズンの新鮮さを両立する。

#### 3.5.4 設定項目とその意味

該当なし（読み取り専用）。

#### 3.5.5 注意点・制約

- 履歴は **編集・削除不可**（履歴改竄を防ぐ）
- 表示名の変更は履歴には反映されない（snapshot 当時の名前で固定）
- 履歴閲覧の専用 UI は本仕様書時点では限定的（polish phase で拡充予定）

### 3.6 シーズン開始日の表示

#### 3.6.1 何ができる機能か

- [/groups/[gid]/season](/groups/%5Bgid%5D/season) と [/groups/[gid]](/groups/%5Bgid%5D) に、現在シーズンの開始日が表示される
- 一度もシーズン切替していない場合は「未設定」と表示

#### 3.6.2 誰が・いつ使うか

- サークルメンバー全員が、現シーズンが何月何日から始まったかを知りたいとき

#### 3.6.3 なぜこの機能が必要か（Why）

シーズンの長さは運営者の判断で変わるため、開始日が表示されることで「今シーズンは何ヶ月続いているのか」が分かりやすくなる。

#### 3.6.4 設定項目とその意味

該当なし（自動表示）。

#### 3.6.5 注意点・制約

- 初回シーズン切替前は「未設定」表示
- 開始日を運営者が任意に書き換えるパスは現状提供していない

### 3.7 シーズン首位カードのダウンロード

#### 3.7.1 何ができる機能か

- [/groups/[gid]/season](/groups/%5Bgid%5D/season) に「画像保存」ボタンが表示される
- ボタンを押すと、シーズン首位（1 位）の名前・順位・累計ポイント・サークル名を入れた PNG 画像が生成・ダウンロードされる
- ダウンロードした画像を LINE / X / その他 SNS にアップロードして共有できる

#### 3.7.2 誰が・いつ使うか

- 運営者・参加者が、シーズン首位を可視化してサークル LINE / X に共有したいとき
- 月初の振り返りや、シーズン切替時の総括として

#### 3.7.3 なぜこの機能が必要か（Why）

「次回も参加しよう」という engagement を維持するため、SNS で素材として貼れる画像が必要。手動スクリーンショットでは見栄えが悪く、共有のハードルになっていた。

#### 3.7.4 設定項目とその意味

該当なし（自動生成）。

#### 3.7.5 注意点・制約

- 画像生成は数秒かかる場合がある（サーバ側で生成）
- 戦績がない（首位がいない）状態ではダウンロードボタンが表示されない
- 画像の文字配置・配色は固定（カスタマイズ不可）

### 3.8 優勝カードのダウンロード（補助）

#### 3.8.1 何ができる機能か

- トーナメントが終了して Winner 演出が表示された画面に「画像保存」ボタンが表示される
- ボタンを押すと、優勝者の名前・順位・トーナメント名・サークル名を入れた PNG 画像が生成・ダウンロードされる
- 共有して LINE / X に貼ることができる

#### 3.8.2 誰が・いつ使うか

- 優勝者本人 / 運営者が、トーナメント直後に SNS で素材として貼りたいとき

#### 3.8.3 なぜこの機能が必要か（Why）

「トーナメントが終わった瞬間、結果を共有したい」という参加者の要望に対応。手動スクリーンショットの代わりに、見栄えの良い画像を 1 タップで取得できる。

#### 3.8.4 設定項目とその意味

該当なし（自動生成）。

#### 3.8.5 注意点・制約

- 画像生成は数秒かかる場合がある
- 画像レイアウトは固定
- 観戦モード URL が未実装のため、現状はサークル所属メンバーのみアクセス可能

## 4. 権限・認可

### 4.1 ロール別操作マトリクス

| 操作 | オーナー | 運営担当者 | 一般メンバー | ゲスト（匿名） |
| --- | --- | --- | --- | --- |
| シーズン戦績の参照（ランキング画面） | ○ | ○ | ○ | × |
| シーズン履歴の参照 | ○ | ○ | ○ | × |
| シーズン開始日の参照 | ○ | ○ | ○ | × |
| シーズンの開始（手動切替） | ○ | ○ | × | × |
| シーズン首位カードのダウンロード | ○ | ○ | ○ | × |
| 優勝カードのダウンロード | ○ | ○ | ○ | △ |
| トーナメント終了時の自動戦績加算 | ○（自動）| ○（自動）| ○（自動）| ×（uid なしのため対象外）|

凡例: ○ 可 / × 不可 / △ ゲストは受付完了画面までしか進まないため、Winner 画面に到達せず実質的にダウンロードできない

### 4.2 ロール定義（spec 内の文脈で）

- **オーナー / 運営担当者**: シーズンの開始操作ができる
- **一般メンバー**: 戦績を閲覧・自分のカードをダウンロードできる
- **ゲスト（匿名）**: シーズン戦績の対象外（uid を持たないため、参加してもポイントが付かない）

### 4.3 補足

- 戦績の自動加算は内部処理。役割に関係なく「uid を持つ参加者」全員が対象
- ゲスト匿名はポイントが付かないため、サークル戦績に積みたい場合は通常アカウントで参加する必要がある
- シーズン開始操作は強い権限のため、オーナー / 運営担当者のみに限定

## 5. 非機能要件（業務観点）

### 5.1 パフォーマンス（体感）

- トーナメント終了時の戦績更新は 1〜2 秒以内に反映
- ランキング画面の表示は 1 秒以内
- 画像カード生成は 1〜数秒（サーバ側生成のため、ネット状況に依存）
- 20 人規模の集計でも遅延なし

### 5.2 セキュリティ（運用方針）

- 戦績データはサークル所属メンバーのみ閲覧可能
- シーズン履歴は **編集・削除不可** という強い制約で改竄を防ぐ
- 戦績の更新はトーナメント終了時の自動処理に限定（運営者でも個別に書き換えはできない）
- 画像カードはサークル所属メンバーのみダウンロード可能

### 5.3 使いやすさ / アクセシビリティ

- ランキング表は表形式で、モバイルでも縦スクロール可能
- 画像カードは大きな文字でデザインされており、SNS 投稿時の視認性が高い
- 数値は小数 2 桁まで表示（細かい順位差も識別可能）

### 5.4 信頼性 / エラー時の挙動

- トーナメント終了時の戦績更新はまとめて確定（失敗時は何も変わらない）
- シーズン切替も同様に、過去戦績の保存と現戦績のリセットが 1 操作で確定する
- 進行中トーナメントがあるときの切替試行は事前検出して止める

### 5.5 保守性 / 運用負担

- ポイント計算式はアプリ内で固定。運営者カスタマイズは未実装（将来拡張）
- シーズン履歴の保持期間に上限はない（実用上問題ない範囲、将来見直し可）
- 戦績のリセットはシーズン切替時のみで、個別メンバーの戦績編集は提供していない

### 5.6 互換性

- シーズン関連のデータ（開始日 / 戦績 / 履歴）は後から追加されたが、過去のサークルでは「未設定」として自動補完される
- 既存トーナメントは初回シーズン切替まで戦績集計対象に含まれる

### 5.7 運用 / 観測性

- 戦績更新・シーズン切替は内部の操作記録に残る
- 画像カードのダウンロード回数は将来的に集計可能（暫定では運営者のヒアリング）
- 障害時はランキング画面の再読み込みで現状確認

## 6. 既知の制約・未対応事項

- **ポイント計算式の運営者カスタマイズなし**: 固定式（順位ベース × 平方根スケール）。サークルごとに変えたい場合は将来拡張で対応
- **シーズン跨ぎの個人累計（all-time 集計）なし**: 現シーズン + 履歴閲覧で代替
- **シーズン履歴の閲覧 UI は限定的**: 過去 N シーズンの一覧を一画面で見る UI は polish phase で拡充予定
- **シーズン自動切替なし**: 毎月 1 日 / 四半期切替などの自動化は未実装。運営者の手動操作のみ
- **戦績の個別修正不可**: 誤バスト時に戦績を補正する経路は提供していない
- **Web Share API 統合（OS シェアシート）は未実装**: 画像保存後に手動で SNS にアップロードする運用
- **画像カードのデザインカスタマイズなし**: 配色・レイアウトは固定
- **シーズン履歴の保持期間制限なし**: 長期運用で履歴が累積する場合は将来見直し
- **シーズン切替時の race condition**: 進行中トーナメント検出は事前チェックで対応するが、検出と切替の間に新規トーナメント終了が走るレースは完全には防げない（影響は軽微）
