# シーズン戦績 業務仕様書

## 1. 概要

サークル単位で **「シーズン」と呼ばれる任意の期間** を設けて、その期間内のトーナメント参加履歴を累計集計する機能。各メンバーの **参加回数・優勝回数・ファイナルテーブル（FT）進出回数・累計ポイント** を自動的に集計し、ランキング画面で確認できる。シーズン区切りは **運営者の手動切替** で行い、過去シーズンは **履歴に snapshot** されて閲覧可能になる。シーズン首位は画像カード PNG としてダウンロードでき、サークル LINE / X に貼って盛り上がり素材にできる。主に [/groups/[gid]/season](/groups/%5Bgid%5D/season) で確認する。

## 2. 想定利用シーン

### 2.1 ペルソナ

- **継続支援を意識する運営者**: 月 1〜2 回開催のサークルで、参加者の継続意欲を維持したい人
- **競技志向の参加者**: 「自分の今シーズンの成績を見たい」「他人と比較したい」と思う人
- **記録共有派**: シーズン首位カードを LINE / X に貼ってサークルを盛り上げたい人

### 2.2 シナリオ

#### 2.2.1 平常系: トーナメント終了とシーズン戦績の自動加算

トーナメントが終了 → 各参加者の参加回数 +1、最終順位に応じてポイントが加算 → 1 位の人は優勝回数 +1、9 位以内なら FT 回数 +1 → ランキング画面でリアルタイムに反映される。

#### 2.2.2 平常系: シーズンランキングの確認

サイドバーから [/groups/[gid]/season](/groups/%5Bgid%5D/season) を開く → 現在シーズンの累計ポイント順で参加者がランキング表示される → 各列で参加・優勝・FT・累計ポイントが確認できる → シーズン開始日も画面上部に表示される。

または、サークル詳細画面 [/groups/[gid]](/groups/%5Bgid%5D) で「シーズン」タブを選ぶだけでも、同じ順位表がその場（タブ内）に表示される。専用のランキング画面まで開かなくても、ワンタップで今シーズンの順位を確認できる。

#### 2.2.3 平常系: シーズン首位カードのダウンロード

[/groups/[gid]/season](/groups/%5Bgid%5D/season) の「シーズン首位カードを保存」ボタンを押す → シーズン首位の PNG カードが生成され、ブラウザの保存ダイアログが出る → 保存して LINE のサークルグループに貼付。

iOS Safari / Android Chrome 等の Web Share API に対応した端末では、保存ボタンの隣に「首位をシェア」ボタンが表示され、押下すると OS シェアシート経由で LINE / X / メール などへ画像とテキストを 1 タップで送れる。Desktop Chrome / Firefox など非対応端末ではシェアボタンは表示されず、保存ボタンのみが見える。

#### 2.2.4 運用系: シーズン手動切替（四半期 / 半期に 1 回）

運営者が「今月で前期シーズン終了、来月から新シーズンを始めたい」と判断 → [/groups/[gid]](/groups/%5Bgid%5D) で「シーズンを開始する」ボタンを押す → 確認ダイアログで「現在の戦績を履歴に保存して、新シーズンを開始しますか？」と表示 → 「開始」を押すと、現シーズンの戦績が履歴に snapshot され、各メンバーの戦績がリセットされ、シーズン開始日が現在時刻に更新される。

#### 2.2.5 失敗系: 進行中のトーナメントがあるときのシーズン切替

運営者が「シーズンを開始する」ボタンを押す → 進行中（受付中・実行中・一時停止中）のトーナメントが 1 件以上存在する → エラーメッセージ「現在進行中のトーナメントがあります。先に終了させてください」が表示 → 運営者は進行中トーナメントを終了させてから再度切替操作を実行。

#### 2.2.5a 運用系: サークル別背景画像で結果カードをブランディング

オーナー B さんが SNS シェアの「サークルらしさ」を高めたいと判断 → [/groups/[gid]](/groups/%5Bgid%5D) の「優勝者カードの背景画像」カードでサークルロゴ風の画像をアップロード → プレビューで文字が読めることを確認し、テキストテーマを「ライト」のまま保存 → 「シーズン首位カードの背景画像」にも同様の画像を設定 → 以降のトーナメント終了時にダウンロードされる優勝カード PNG と、シーズン首位カードの両方が新しい背景で出力されるようになる → LINE のサークルグループに貼ると、誰のサークルか一目で識別できる。

#### 2.2.6 運用系: 過去シーズンの履歴閲覧

運営者が「先月の首位は誰だったか」を確認したいとき、[/groups/[gid]/season](/groups/%5Bgid%5D/season) ページ最下部の「過去シーズン」セクションで履歴を閲覧できる。各シーズン行には開始日〜終了日と首位の表示名・累計ポイントが並び、右側の「詳細を見る」を押すと専用ページ [/groups/[gid]/season/history/[seasonId]](/groups/%5Bgid%5D/season/history/%5BseasonId%5D) が開き、現在シーズンと同じ列構成（順位 / 表示名 / 参加 / 優勝 / FT / 累計ポイント）で全員分のランキングが表示される。詳細ページからはシーズン首位カードの保存・シェアも行える。履歴 0 件のサークルではセクション自体が表示されない。

## 3. 機能要件

### 3.1 シーズン戦績の自動集計

#### 3.1.1 何ができる機能か

- トーナメントが「終了」状態になると、各参加者のシーズン戦績が自動的に更新される
- 更新内容: **参加回数 +1**、最終順位に応じた **累計ポイント加算**、1 位なら **優勝回数 +1**、9 位以内なら **FT 進出回数 +1**
- 更新はまとめて確定される（途中で失敗した場合は何も変わらない）
- 同じトーナメントが複数回終了することはない設計（二重加算なし）

#### 3.1.2 誰が・いつ使うか

- 全メンバーのシーズン戦績は自動で更新される
- 運営者は「シーズン戦績を更新する」ボタンを押す必要なし

#### 3.1.3 なぜこの機能が必要か（Why）

参加者の継続意欲を維持するため、サークルでの自分の活動が「累計として見える」ことが重要。手動で集計せず自動で進む設計にすることで、運営者の負担なしに戦績が積み上がる。

#### 3.1.4 設定項目とその意味

該当なし（自動集計）。トーナメント終了時の参加人数で自動的にポイントが計算される。

#### 3.1.5 注意点・制約

- ゲスト匿名（uid なし）の参加者は集計対象外
- バストした人も「参加した」とカウントされる
- トーナメント終了後にバストを取り消す UI は提供していない（取り消した場合の戦績再計算もない）

### 3.2 ポイント計算式（既定値とカスタマイズ）

#### 3.2.1 何ができる機能か

- ポイントは **「順位ベース × 参加人数係数」** で計算される
  - 既定の順位ベース: 1 位: 10 / 2 位: 7 / 3 位: 5 / 4 位: 3 / 5〜9 位: 1 / 10 位以下: 0
  - 参加人数係数: √(参加人数 / 基準人数)
  - 既定の基準人数: 8 名
  - 例: 既定値で 6 人開催の 1 位 = 10 × √(6/8) ≈ 8.66pt、20 人開催の 1 位 = 10 × √(20/8) ≈ 15.81pt
- 小数 2 桁で保持（表示時の四捨五入は画面側）
- **運営者は順位ベース配列と基準人数をサークル単位でカスタマイズできる**（3.10 節参照）

#### 3.2.2 誰が・いつ使うか

- ポイントはアプリが自動算出するため、運営者・参加者は意識しない（カスタマイズ操作以外）
- カスタマイズはオーナー / 運営担当者がサークル運営方針を決めるとき

#### 3.2.3 なぜこの機能が必要か（Why）

「6 人と 20 人で同じ 10pt では違和感がある」という運営者要望に対応するため、参加人数で重みをつける式を採用している。平方根スケールを使うことで、人数増による差が極端になりすぎないバランスを取っている。サークルごとに常用人数や順位差の重視度合いが違うため、運営者がカスタマイズできる経路も提供している。

#### 3.2.4 設定項目とその意味

| 項目 | 既定値 | 業務上の意味 |
| --- | --- | --- |
| 1 位 base ポイント | 10 | 最高順位の固定ベース |
| 2 位 base | 7 | 上位 3 位までの差を残す |
| 3 位 base | 5 | 同上 |
| 4 位 base | 3 | 4 位の小さなご褒美 |
| 5〜9 位 base | 1 | FT 進出最低ポイント |
| 10 位以下 | 0 | ポイントなし（既定では 9 個までの順位ベースを定義し、それ以降は 0） |
| 参加人数係数の基準値 | 8 名 | 1 卓フル運用を「係数 1.0」とする |
| FT しきい値 | 9 位以内 | NLH 9 人卓に揃えた基準 |

順位ベース配列と基準人数は運営者がカスタマイズ可能。FT しきい値（9 位以内）はカスタマイズ対象外（アプリ全体で固定）。

#### 3.2.5 注意点・制約

- カスタマイズ後は、**そのトーナメント終了時点での計算式** が採用される（既に終了したトーナメントの戦績は遡及更新されない）
- 同点（同順位）処理は内部で決定論的に行われる
- 浮動小数点誤差は 2 桁丸めで防止
- カスタマイズ手順は 3.10 節を参照

### 3.3 シーズンランキング画面

#### 3.3.1 何ができる機能か

- [/groups/[gid]/season](/groups/%5Bgid%5D/season) で、現在シーズンの戦績ランキングを表示
- 各メンバーの順位 / 表示名 / 参加回数 / 優勝回数 / FT 回数 / 累計ポイントを表で確認
- 累計ポイント降順で並び替え（同点時は内部順）
- シーズン開始日が画面上部に表示される
- 「画像保存」ボタンでシーズン首位カードをダウンロード（後述）
- **同じ順位表は、サークル詳細画面 [/groups/[gid]](/groups/%5Bgid%5D) の「シーズン」タブを開くだけでもインライン表示される**。専用のランキング画面まで遷移しなくても、タブを選んだその場で今シーズンの順位（同じ列構成）が見える。表示はリアルタイムで自動更新される。戦績がまだない（このシーズンでトーナメントを終えていない）ときは順位表は出さず「戦績はまだありません」という案内に倒れる

#### 3.3.2 誰が・いつ使うか

- サークルメンバー全員が、自分・他人の戦績を確認したいとき
- 運営者がシーズン振り返りを行いたいとき

#### 3.3.3 なぜこの機能が必要か（Why）

「先月の首位は誰だったか」「自分は何位くらいか」を可視化することで、参加者の継続意欲フックになる。サークルランキングが動的に見えることで、参加の動機が増える。

#### 3.3.4 設定項目とその意味

該当なし（読み取り専用）。

#### 3.3.5 注意点・制約

- サークルメンバー全員が閲覧可能
- 戦績がまだない（このシーズンでトーナメントを終えていない）状態では「戦績はまだありません」と表示
- サークル詳細画面の「シーズン」タブのインライン順位表と、専用のランキング画面 [/groups/[gid]/season](/groups/%5Bgid%5D/season) は同じ内容を表示する。シーズン首位カードのダウンロード / シェアや過去シーズン履歴は専用のランキング画面側にある（[02-circles-and-membership.spec.md](02-circles-and-membership.spec.md) のサークル詳細タブ構成も参照）

### 3.4 シーズンの開始（手動切替）

#### 3.4.1 何ができる機能か

- [/groups/[gid]](/groups/%5Bgid%5D) で「シーズンを開始する」ボタン（オーナー / 運営担当者のみ表示）
- 確認ダイアログで「現在の戦績を履歴に保存して、新シーズンを開始します」と告知
- 「開始」を押すと:
  1. 現在の戦績全件を履歴に snapshot
  2. シーズン開始日を現在時刻に更新
  3. 各メンバーの戦績を 0 にリセット
- まとめて確定されるため、途中で失敗したら何も変わらない

#### 3.4.2 誰が・いつ使うか

- サークルの運営者が、四半期 / 半期 / 年度の区切りで新シーズンを始めたいとき

#### 3.4.3 なぜこの機能が必要か（Why）

サークルごとに開催ペースが違うため、自動切替（毎月 1 日 / 4 月 1 日 など）よりも運営者の判断で柔軟に切替えられる方が運用に合う。過去シーズンを履歴として残すことで、「先月の首位」の参照も可能。

#### 3.4.4 設定項目とその意味

該当なし（ボタン操作 + 確認ダイアログ）。

#### 3.4.5 注意点・制約

- **進行中のトーナメント（受付中・実行中・一時停止中）が 1 件でもあるとシーズン切替不可**（エラーメッセージ）
- 進行中トーナメントの終了後にシーズン切替するのは、運営者が「先に終了 → シーズン切替」の順で操作する
- シーズン切替の取り消しはできない（履歴は残るが、戦績の戻しは不可）
- 一般メンバーには「シーズンを開始する」ボタンが表示されない

### 3.5 シーズン履歴

#### 3.5.1 何ができる機能か

- 過去シーズンの戦績スナップショットがサークル単位で保存される
- 各履歴には開始時刻・終了時刻と参加者の戦績エントリが含まれる
- 履歴は閲覧のみ可能（編集・削除はできない）
- サークルメンバー全員が閲覧可能
- [/groups/[gid]/season](/groups/%5Bgid%5D/season) ページ最下部の「過去シーズン」セクションに新しい順（終了日降順）で一覧表示される。各行に並ぶ「詳細を見る」を押すと専用詳細ページ [/groups/[gid]/season/history/[seasonId]](/groups/%5Bgid%5D/season/history/%5BseasonId%5D) が開き、全員分のランキング（順位 / 表示名 / 参加 / 優勝 / FT / 累計ポイント）が現在シーズンと同じ列構成で表示される
- 詳細ページの URL を共有すれば、サークル LINE 等から直接該当シーズンの詳細ページを開ける
- 詳細ページからはシーズン首位カードの保存（PNG ダウンロード）と Web Share API 対応端末でのシェアボタンが利用できる

#### 3.5.2 誰が・いつ使うか

- 運営者・参加者が「先月の首位は誰だったか」を確認したいとき
- 過去シーズンの自分の成績を振り返りたいとき

#### 3.5.3 なぜこの機能が必要か（Why）

シーズンの区切りで戦績がリセットされるが、過去のシーズンの記録を完全に消すと「あのシーズンの首位はあの人だった」という思い出が失われる。履歴として保存することで、長期的な記録と現シーズンの新鮮さを両立する。

#### 3.5.4 設定項目とその意味

該当なし（読み取り専用）。

#### 3.5.5 注意点・制約

- 履歴は **編集・削除不可**（履歴改竄を防ぐ）
- 表示名の変更は履歴には反映されない（snapshot 当時の名前で固定）
- 履歴 0 件のサークルでは「過去シーズン」セクション自体が表示されない
- 詳細ページに直リンクで非メンバーがアクセスした場合は「見つかりません」UI に倒れる（認可情報を leak しない）

### 3.6 シーズン開始日の表示

#### 3.6.1 何ができる機能か

- [/groups/[gid]/season](/groups/%5Bgid%5D/season) と [/groups/[gid]](/groups/%5Bgid%5D) に、現在シーズンの開始日が表示される
- 一度もシーズン切替していない場合は「未設定」と表示

#### 3.6.2 誰が・いつ使うか

- サークルメンバー全員が、現シーズンが何月何日から始まったかを知りたいとき

#### 3.6.3 なぜこの機能が必要か（Why）

シーズンの長さは運営者の判断で変わるため、開始日が表示されることで「今シーズンは何ヶ月続いているのか」が分かりやすくなる。

#### 3.6.4 設定項目とその意味

該当なし（自動表示）。

#### 3.6.5 注意点・制約

- 初回シーズン切替前は「未設定」表示
- 開始日を運営者が任意に書き換えるパスは現状提供していない

### 3.7 シーズン首位カードのダウンロード / シェア

#### 3.7.1 何ができる機能か

- [/groups/[gid]/season](/groups/%5Bgid%5D/season) に「シーズン首位カードを保存」ボタンが表示される
- ボタンを押すと、シーズン首位（1 位）の名前・順位・累計ポイント・サークル名を入れた PNG 画像が生成・ダウンロードされる
- ダウンロードした画像を LINE / X / その他 SNS にアップロードして共有できる
- Web Share API に対応した端末（iOS Safari / Android Chrome）では保存ボタンの隣に「首位をシェア」ボタンが**並列表示**され、押下で OS シェアシート経由で 1 タップ送信できる。非対応端末では保存ボタンのみが表示される
- **サークル設定でシーズン首位カードの背景画像が登録されている場合、その画像が背景に重ねて出力される**（未設定なら既定の単色グラデーション背景）。背景画像と一緒にテキストテーマ（ライト / ダーク）も反映される。詳細は 3.11 節を参照

#### 3.7.2 誰が・いつ使うか

- 運営者・参加者が、シーズン首位を可視化してサークル LINE / X に共有したいとき
- 月初の振り返りや、シーズン切替時の総括として

#### 3.7.3 なぜこの機能が必要か（Why）

「次回も参加しよう」という engagement を維持するため、SNS で素材として貼れる画像が必要。手動スクリーンショットでは見栄えが悪く、共有のハードルになっていた。

#### 3.7.4 設定項目とその意味

該当なし（自動生成）。

#### 3.7.5 注意点・制約

- 画像生成は数秒かかる場合がある（サーバ側で生成）
- 戦績がない（首位がいない）状態ではダウンロードボタンが表示されない
- 画像の文字配置・配色は固定（カスタマイズ不可）

### 3.8 優勝カードのダウンロード / シェア（補助）

#### 3.8.1 何ができる機能か

- トーナメントが終了して Winner 演出が表示された画面に「画像を保存」ボタンが表示される
- ボタンを押すと、優勝者の名前・順位・トーナメント名・サークル名を入れた PNG 画像が生成・ダウンロードされる
- 共有して LINE / X に貼ることができる
- Web Share API に対応した端末では保存ボタンの隣に「シェア」ボタンが**並列表示**され、押下で OS シェアシート経由で 1 タップ送信できる。非対応端末では保存ボタンのみが表示される
- **サークル設定で優勝者カードの背景画像が登録されている場合、その画像が背景に重ねて出力される**（未設定なら既定の単色グラデーション背景）。テキストテーマ（ライト / ダーク）の選択も合わせて反映される。詳細は 3.11 節を参照

#### 3.8.2 誰が・いつ使うか

- 優勝者本人 / 運営者が、トーナメント直後に SNS で素材として貼りたいとき

#### 3.8.3 なぜこの機能が必要か（Why）

「トーナメントが終わった瞬間、結果を共有したい」という参加者の要望に対応。手動スクリーンショットの代わりに、見栄えの良い画像を 1 タップで取得できる。

#### 3.8.4 設定項目とその意味

該当なし（自動生成）。

#### 3.8.5 注意点・制約

- 画像生成は数秒かかる場合がある
- 画像レイアウトは固定
- 優勝カードのダウンロード / シェアは Winner 画面（運営者ダッシュボード / 参加者向け表示）に到達できる人のみが対象。観戦経路（[/spectate/[tid]](/spectate/%5Btid%5D)）は読み取り専用のためダウンロードボタン自体が表示されない

### 3.10 シーズンポイント計算式の運営者カスタマイズ

#### 3.10.1 何ができる機能か

- [/groups/[gid]](/groups/%5Bgid%5D) のサークル詳細画面に「シーズンポイント計算式」のカードがあり、サークル単位で計算式をカスタマイズできる
- 設定できる項目:
  - **順位ベース配列**（1〜9 個の非負数値、各要素は 0 以上）— 1 位から並び、配列長を超えた順位は 0pt
  - **参加人数の基準値**（2〜10 の整数）— 「係数 1.0 になる人数」
- 「既定値に戻す」ボタンで元の式（base = [10, 7, 5, 3, 1, 1, 1, 1, 1] / 基準 8 名）に戻せる
- 設定後の **次回トーナメント終了から** 新しい計算式が適用される

#### 3.10.2 誰が・いつ使うか

- オーナー / 運営担当者が、サークル運営方針として「もっと優勝重視にしたい」「順位差を緩やかにしたい」と判断したとき
- サークルの常用人数（毎回 6 人とか 12 人とか）に合わせて基準人数を変えたいとき

#### 3.10.3 なぜこの機能が必要か（Why）

サークルごとに常用人数や運営方針が違うため、固定の計算式ではフィット感に欠ける。運営者がベース配列と基準人数を自由に変えられることで、サークルの「ポイント文化」を作れる。一方で、FT しきい値（9 位以内）など TDA ルールに紐づく値はカスタマイズ対象外として、共通指標の互換性を保っている。

#### 3.10.4 設定項目とその意味

| 項目 | 入力形式 | 推奨 / 既定値 | 業務上の意味 |
| --- | --- | --- | --- |
| 順位ベース配列 | 1〜9 個の非負数値 | [10, 7, 5, 3, 1, 1, 1, 1, 1] | 1 位から順番に何 pt のベースを与えるか |
| 参加人数の基準値 | 2〜10 の整数 | 8 名 | この人数で係数 1.0、それ以上は 1.0 超、それ以下は 1.0 未満 |

#### 3.10.5 注意点・制約

- カスタマイズ後の計算式は **次回のトーナメント終了から** 適用される。既に終了したトーナメントの戦績は再計算されない
- ベース配列は最大 9 個まで（NLH 9 人卓に揃えた上限）。それ以降の順位は常に 0pt
- 既定値に戻すと、現サークルの計算式が初期化される（ただし過去のトーナメント終了時点の戦績は影響を受けない）
- 進行中のトーナメントがあるときに変更しても、終了時点の最新値が適用される
- 大きく変更した場合は「シーズンを開始する」で戦績をリセットしたほうが、参加者にとって公平に感じやすい（現シーズン途中で計算式を変えると、過去ポイントと新ポイントの密度が変わる）

### 3.11 結果カード背景画像のカスタマイズ（サークル別ブランディング）

#### 3.11.1 何ができる機能か

- サークル詳細画面 [/groups/[gid]](/groups/%5Bgid%5D) に **「優勝者カードの背景画像」** と **「シーズン首位カードの背景画像」** の 2 枚のカードがあり、サークル単位で独自の背景画像を 2 種類設定できる
- それぞれのカードでできる操作:
  - 画像ファイルをアップロードして背景に設定（カード内のファイル選択ボタン）
  - 「ライト / ダーク」のテキストテーマを切り替える
  - **プレビュー**: 保存前に「実際のシェアカードでどう見えるか」を確認できる
  - 「解除」ボタンで既定の単色背景に戻す
- 保存すると、以降に生成される該当カード（優勝カード / シーズン首位カード）にすぐ反映される
- 既存サークル（未設定）の挙動は従来通りで、設定するまで何も変わらない（破壊的な変更ではない）

#### 3.11.2 誰が・いつ使うか

- **オーナーのみ**（運営担当者・一般メンバーには編集 UI が表示されない）
- サークル設立後のブランディング設定 / 新シーズン開始時のリブランド / 大会前の特別仕様 など

#### 3.11.3 なぜこの機能が必要か（Why）

シーズン首位カードや優勝カードを LINE / X で共有したとき、画一的なテンプレートだと「どこのサークルか」が伝わりにくく、運営者から「サークルらしさを出したい / 新規勧誘の素材として使いたい」要望があった。サークル単位で 2 枚（優勝者用・シーズン首位用）の背景画像を差し替えられることで、共有時の識別性とサークル内エンゲージメントを高める。**設定者をオーナーに限定** することで、ブランドの一貫性を保ち、複数の運営担当者で意図せず競合する事故を防ぐ。

#### 3.11.4 設定項目とその意味

| 項目 | 入力形式 | 推奨 / 既定値 | 業務上の意味 |
| --- | --- | --- | --- |
| 優勝者カードの背景画像 | 画像ファイル（JPEG / PNG 等、5MB 以下推奨）| 既定なし（単色グラデーション）| トーナメント終了時の優勝カードに反映 |
| シーズン首位カードの背景画像 | 同上 | 同上 | シーズンランキングの首位カードに反映 |
| テキストテーマ | ライト / ダーク | ライト | 画像の明るさに合わせて文字色と読みやすさレイヤを切り替え |

#### 3.11.5 注意点・制約

- **設定はオーナーのみ**。運営担当者・一般メンバーには編集 UI が表示されない
- **アップロード画像は公開 URL として配信される**（結果カード PNG を共有された相手のブラウザがアクセスする経路）。**機密画像・個人情報を含む画像はアップロードしない**
- 推奨サイズは 1200×630 px 前後。アプリは自動でこのサイズに圧縮するため、原寸が大きくても問題ないが、5MB を超えるファイルは事前に reject される
- 画像差し替え時、古い画像は自動的に削除される（最大 3 回まで再試行）。すべて失敗した場合でも新画像の保存は成功扱いになり、結果カードは新画像で正常に生成される（残った古い画像は次回上書き時には自動清掃の対象外になる既知の制約あり）
- 任意の画像に対する文字の読みやすさは、上下のグラデーションスクリム / 局所的な半透明帯 / テキストテーマ切替の三段構えで対応。明るすぎる画像 + 白文字 のような組み合わせはプレビューで事前確認するのが安全
- 画像のレイアウト（文字位置・サイズ）は固定。背景のみを差し替える設計
- カード PNG はキャッシュされるため、画像を差し替えた直後の数分間は古い PNG が出る可能性がある（自動でキャッシュは更新される）

## 4. 権限・認可

### 4.1 ロール別操作マトリクス

| 操作 | オーナー | 運営担当者 | 一般メンバー | ゲスト（匿名） |
| --- | --- | --- | --- | --- |
| シーズン戦績の参照（ランキング画面） | ○ | ○ | ○ | × |
| シーズン履歴の参照 | ○ | ○ | ○ | × |
| シーズン開始日の参照 | ○ | ○ | ○ | × |
| シーズンの開始（手動切替） | ○ | ○ | × | × |
| シーズン首位カードのダウンロード / シェア | ○ | ○ | ○ | × |
| 優勝カードのダウンロード / シェア | ○ | ○ | ○ | △ |
| トーナメント終了時の自動戦績加算 | ○（自動）| ○（自動）| ○（自動）| ×（uid なしのため対象外）|
| シーズンポイント計算式の参照 | ○ | ○ | ○ | × |
| シーズンポイント計算式のカスタマイズ | ○ | ○ | × | × |
| 結果カード背景画像 / テキストテーマの参照（プレビュー / 適用後の見え方） | ○ | ○ | ○ | × |
| 結果カード背景画像 / テキストテーマの設定（アップロード・解除）| ○ | × | × | × |

凡例: ○ 可 / × 不可 / △ ゲストは受付完了画面までしか進まないため、Winner 画面に到達せず実質的にダウンロードできない

### 4.2 ロール定義（spec 内の文脈で）

- **オーナー / 運営担当者**: シーズンの開始操作ができる
- **一般メンバー**: 戦績を閲覧・自分のカードをダウンロードできる
- **ゲスト（匿名）**: シーズン戦績の対象外（uid を持たないため、参加してもポイントが付かない）

### 4.3 補足

- 戦績の自動加算は内部処理。役割に関係なく「uid を持つ参加者」全員が対象
- ゲスト匿名はポイントが付かないため、サークル戦績に積みたい場合は通常アカウントで参加する必要がある
- シーズン開始操作は強い権限のため、オーナー / 運営担当者のみに限定

## 5. 非機能要件（業務観点）

### 5.1 パフォーマンス（体感）

- トーナメント終了時の戦績更新は 1〜2 秒以内に反映
- ランキング画面の表示は 1 秒以内
- 画像カード生成は 1〜数秒（サーバ側生成のため、ネット状況に依存）
- 20 人規模の集計でも遅延なし

### 5.2 セキュリティ（運用方針）

- 戦績データはサークル所属メンバーのみ閲覧可能
- シーズン履歴は **編集・削除不可** という強い制約で改竄を防ぐ
- 戦績の更新はトーナメント終了時の自動処理に限定（運営者でも個別に書き換えはできない）
- 画像カードはサークル所属メンバーのみダウンロード可能

### 5.3 使いやすさ / アクセシビリティ

- ランキング表は表形式で、モバイルでも縦スクロール可能
- 画像カードは大きな文字でデザインされており、SNS 投稿時の視認性が高い
- 数値は小数 2 桁まで表示（細かい順位差も識別可能）

### 5.4 信頼性 / エラー時の挙動

- トーナメント終了時の戦績更新はまとめて確定（失敗時は何も変わらない）
- シーズン切替も同様に、過去戦績の保存と現戦績のリセットが 1 操作で確定する
- 進行中トーナメントがあるときの切替試行は事前検出して止める

### 5.5 保守性 / 運用負担

- ポイント計算式はサークル単位でカスタマイズ可能。既定値に戻す経路もあり、設定ミスは即座に復旧できる
- カスタマイズ変更は次回トーナメント終了から適用されるため、過去戦績への影響を心配せず触れる
- シーズン履歴の保持期間に上限はない（実用上問題ない範囲、将来見直し可）
- 戦績のリセットはシーズン切替時のみで、個別メンバーの戦績編集は提供していない

### 5.6 互換性

- シーズン関連のデータ（開始日 / 戦績 / 履歴）は後から追加されたが、過去のサークルでは「未設定」として自動補完される
- 既存トーナメントは初回シーズン切替まで戦績集計対象に含まれる

### 5.7 運用 / 観測性

- 戦績更新・シーズン切替は内部の操作記録に残る
- 画像カードのダウンロード回数は将来的に集計可能（暫定では運営者のヒアリング）
- 障害時はランキング画面の再読み込みで現状確認

## 6. 既知の制約・未対応事項

- **シーズン跨ぎの個人累計（all-time 集計）なし**: 現シーズン + 履歴閲覧で代替
- **シーズン自動切替なし**: 毎月 1 日 / 四半期切替などの自動化は未実装。運営者の手動操作のみ
- **戦績の個別修正不可**: 誤バスト時に戦績を補正する経路は提供していない
- **Web Share API 統合は対応端末のみ**: iOS Safari / Android Chrome 等では保存と並列でシェアボタンが出るが、Desktop Chrome / Firefox では保存ボタンのみ。OS シェアシート未対応端末でも画像保存 → 手動アップロードで運用可
- **画像カードのレイアウトカスタマイズなし**: 文字位置・サイズなどは固定。サークル単位で変えられるのは背景画像とテキストテーマ（ライト / ダーク）のみ
- **背景画像の設定者拡張なし**: 設定はオーナーに限定。運営担当者・一般メンバーへの拡張は未対応
- **個別トーナメントごとの背景設定なし**: 設定はサークル単位（優勝者用 / シーズン首位用の 2 枚）まで。「このトーナメントだけ別の画像」のような per-tournament 設定は未対応
- **背景画像差し替え時の古い画像 orphan 残留の可能性**: 自動削除は最大 3 回まで再試行するが、すべて失敗した場合は古い画像が残ったままになる（結果カード自体は新画像で正常に生成される）
- **シーズン履歴の保持期間制限なし**: 長期運用で履歴が累積する場合は将来見直し
- **シーズン切替時の race condition**: 進行中トーナメント検出は事前チェックで対応するが、検出と切替の間に新規トーナメント終了が走るレースは完全には防げない（影響は軽微）
