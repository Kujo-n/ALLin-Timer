# ALLin-PokerTimer 業務仕様書 — 全体像と索引

## 1. サービス全体像

**ALLin-PokerTimer** は、20 人前後のサークル単位で **ノーリミットテキサスホールデム（NLH）のトーナメント** を進行するための Web アプリケーション。月 1〜2 回の定期開催を想定し、**熟練したトーナメントディレクター（TDA）が不在** でも、アプリが席決め・卓間バランシング・ブラインド進行を自動指示することで、運営担当者がプレイヤーを兼任しながらでもルール通りに運営できる設計になっている。サークルごとの運営方針（席数・Table 名・サウンド設定・シーズン戦績）も柔軟にカスタマイズでき、シーズン首位の画像カードを LINE / X に共有してサークル継続性を支える機能も備えている。MIT ライセンスで GitHub に公開されており、サークル固有のデータは外部のデータベース（Firestore）にのみ保存される。

主要ペルソナ:

- **オーナー**: サークルの最終責任者。サークル名・役割・全設定を管理する
- **運営担当者**: トーナメント運営の実務担当。当日のタイマー・席決め・バランシング指示を実行
- **一般メンバー**: サークルに加入してトーナメントに参加するメンバー
- **ゲスト（匿名）**: 当日初参加のライト勢。表示名のみで受付できる

- **ロール**: 同じユーザーがサークル A ではオーナー、サークル B では一般メンバー、というように、サークルごとに異なるロールを持てる

## 5. 全体ポリシー

### 5.1 セキュリティの考え方

- データベースは「既定では誰も触れない」設計。所属サークルのメンバーにのみ必要な権限を開ける
- MIT ライセンスでアプリのコードは公開しているが、サークル固有のデータ（参加者名・トーナメント記録・シーズン戦績）はリポジトリには含めず、クラウド上のデータベースにのみ保存する
- サインイン方式は **Google / メール+PW / 匿名（ゲスト）** の 3 種類。匿名ゲストはトーナメント受付のみで使え、運営機能には触れない
- 招待リンクは推測困難な文字列で発行され、有効期限と最大利用回数を設定可能（最大利用回数の UI は本仕様書時点では未実装）

### 5.2 信頼性の考え方

- 通信エラーが起きた場合は「接続切れ」のバッジと最後の同期時刻が画面に表示される（誤情報を出さない）
- 複数の更新が必要な操作（席決め / 終了時のシーズン戦績更新 など）は **まとめて確定** される（途中で失敗したら何も変わらない）
- 同じ操作が二重実行された場合は、まとめて確定の仕組みで自動的に弾かれる（受付の二重登録など）

### 5.3 使いやすさの考え方

- スマホ・タブレット・PC で同じように動作する
- 主要操作はキーボード（PC）とタップ（スマホ）の両方で可能
- タイマー文字は遠見対応の大きさ。会場の大型ディスプレイへの投影もサポート
- 文字サイズ・色のコントラストは見やすさを優先
- 視覚（バナー / Winner 演出）と聴覚（音声通知）の両方で進行を伝達

### 5.4 運用の考え方

- 操作ログ（バスト / 席移動 / シーズン切替など）は内部に記録される
- 障害時は運営者が画面を再読み込みすることで現状確認できる
- 監視ダッシュボード / アラート機能は本仕様書時点では未整備。運営者が手動で確認する

## 7. 既知の全体制約

業務に影響する範囲だけを箇条書きで:

- **対象規模**: 6 卓以下 / 20 人前後のサークル開催を想定。7 卓以上の運用は対応外（卓間バランシングのルールが変わるため）
- **多言語対応**: 日本語のみ。英語・他言語の表示には未対応
- **モバイルアプリ（ネイティブ）は提供していない**: Web ブラウザのみ。PWA 化（ホーム画面追加）も未実装
- **監視 / アラートは未整備**: 障害発生時は運営者が手動で確認する
- **観戦モード URL は未実装**: トーナメントを外部の観客が見るための URL はまだ提供しない
- **リバイ・アドオンの実行操作は未実装**: ストラクチャに量フィールドはあるが、実行 UI はない
- **賞金計算（ICM 含む）は未実装**
- **シーズン戦績の結果カード PNG ダウンロード**: シーズン首位カード・優勝カードは現在開発中（暫定で利用可能）。Web Share API（OS シェアシート）への統合は未実装で、画像保存後に手動で SNS にアップロードする運用
- **音声通知のカスタム音源アップロードは未実装**: デフォルト音源 2 種類のみ
- **招待リンクの最大利用回数 UI は未実装**: 現状は上限なしで運用
- **テンプレート管理者の付与・剥奪 UI は未実装**: 運営チームが直接データベース上で設定する必要がある
- **ポイント計算式の運営者カスタマイズは未実装**: 順位ベース × 平方根スケールで固定
- **シーズン履歴の閲覧 UI は限定的**: 過去 N シーズンの一覧表示は polish phase で拡充予定
- **シーズン自動切替（毎月 1 日 / 4 月 1 日 など）は未実装**: 運営者の手動操作のみ

詳細は各個別 spec の「6. 既知の制約・未対応事項」を参照。
