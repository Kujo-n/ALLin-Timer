# ALLin-PokerTimer 業務仕様書 — 全体像と索引

## 1. サービス全体像

**ALLin-PokerTimer** は、20 人前後のサークル単位で **ノーリミットテキサスホールデム（NLH）のトーナメント** を進行するための Web アプリケーション。月 1〜2 回の定期開催を想定し、**熟練したトーナメントディレクター（TDA）が不在** でも、アプリが席決め・卓間バランシング・ブラインド進行を自動指示することで、運営担当者がプレイヤーを兼任しながらでもルール通りに運営できる設計になっている。サークルごとの運営方針（席数・Table 名・サウンド設定・シーズン戦績・ポイント計算式・結果カードの背景画像）も柔軟にカスタマイズでき、シーズン首位や優勝者の画像カードを LINE / X に共有してサークル継続性を支える機能も備えている。**スマートフォンのホーム画面に追加すると専用アプリのような見た目で起動でき、会場の一時的な通信障害でもタイマーが止まらない設計**で、月 1〜2 回開催の運用に耐える。さらに **運営者が opt-in で公開する観戦専用 URL** を発行できるため、会場の予備モニタへの投影や遅刻参加者への状況共有がログインなしで完結する。アプリ全体の **色調（ライト / ダーク / OS 設定追従）は端末ごとの個人 preference として選択でき**、暗い会場でも目に優しいダークパレットを既定で OS 設定追従にして提供する。トップ画面 [/](/) からは、運営者がアプリ概要 / 運営チートシートとして書いた外部の note 記事 2 本へリンクが貼られており、新規メンバーへの紹介や当日の運営確認に使える（記事 URL は環境変数で管理され、リポジトリには公開しない）。当日の現場オペレーションにも配慮しており、**スマホの充電切れ等で本人が受付できない参加者を運営者が代理登録**できるほか、**脱落者用に卓を空けて閉じる / 人数増で卓を増やす・閉じた卓を再開する** といった卓数の手動コントロールにも対応する。参加者側の手順も **受付 QR 1 枚に集約**されており、ゲスト以外の方法で受付すると同時にそのサークルのメンバーにも自動登録されるため、サークル加入用の QR を別途配る必要がない（誤って入った人はオーナーが除外できる）。MIT ライセンスで GitHub に公開されており、サークル固有のデータは外部のデータベース（Firestore）にのみ保存される。

主要ペルソナ:

- **オーナー**: サークルの最終責任者。サークル名・役割・全設定を管理する
- **運営担当者**: トーナメント運営の実務担当。当日のタイマー・席決め・バランシング指示を実行
- **一般メンバー**: サークルに加入してトーナメントに参加するメンバー
- **ゲスト（匿名）**: 当日初参加のライト勢。表示名のみで受付できる

## 5. 全体ポリシー

### 5.1 セキュリティの考え方

- データベースは「既定では誰も触れない」設計。所属サークルのメンバーにのみ必要な権限を開ける
- MIT ライセンスでアプリのコードは公開しているが、サークル固有のデータ（参加者名・トーナメント記録・シーズン戦績）はリポジトリには含めず、クラウド上のデータベースにのみ保存する
- サインイン方式は **Google / メール+PW / 匿名（ゲスト）** の 3 種類。匿名ゲストはトーナメント受付のみで使え、運営機能には触れない
- 招待リンクは推測困難な文字列で発行され、有効期限と最大利用回数を設定可能（最大利用回数の UI は本仕様書時点では未実装）
- **同じサークルで招待リンクを再発行すると、直前のリンクは自動的に無効化される**（流出を疑ったら再発行で取り戻せる運用）
- サークルへの加入経路は **招待リンク** と **トーナメント受付による自動加入** の 2 つ。どちらも「一般メンバー」から始まり、運営権限は付かない。自動加入は受付できる状態のトーナメントに限られ、終了済みトーナメントの QR は加入経路にならない
- **受付 QR を見せた相手はサークルに入れる**ことになるため、QR は「サークルに入れてよい相手」にのみ提示する運用が前提。誤って入った人はオーナーが除外できる（[02-circles-and-membership.spec.md](02-circles-and-membership.spec.md)）
- ゲスト（匿名）はどちらの経路でもサークルに加入しない
- 古いゲスト匿名アカウントは、**アプリ管理者の定期清掃スクリプト** で「7 日以上前に作成された / どの SNS 連携も持たない」アカウントを整理する運用に倒している（参加者一覧やシーズン戦績は参加当時の表示名のまま残す）
- トップ画面の note 記事リンクは **環境変数で URL を管理** することで、MIT 公開リポジトリに運営者個人の URL を残さない設計

### 5.2 信頼性の考え方

- 通信エラーが起きた場合は「接続切れ」のバッジと最後の同期時刻が画面に表示される（誤情報を出さない）
- 一時的な通信障害でも **タイマー進行は止まらず、復帰時に状態が同期される**（会場 Wi-Fi 不安定の運用に耐える設計）
- 複数の更新が必要な操作（席決め / 終了時のシーズン戦績更新 など）は **まとめて確定** される（途中で失敗したら何も変わらない）
- 同じ操作が二重実行された場合は、まとめて確定の仕組みで自動的に弾かれる（受付の二重登録など）
- トーナメント終了（優勝確定）はオフライン中は実行できず、運営者に再試行を促す（集計の正しさを保つため）

### 5.3 使いやすさの考え方

- スマホ・タブレット・PC で同じように動作する
- 主要操作はキーボード（PC）とタップ（スマホ）の両方で可能
- タイマー文字は遠見対応の大きさ。会場の大型ディスプレイへの投影もサポート
- 文字サイズ・色のコントラストは見やすさを優先（ライト / ダークの両配色とも WCAG AA 相当）
- 視覚（バナー / Winner 演出）と聴覚（音声通知）の両方で進行を伝達
- **テーマ切替**: ライト / ダーク / OS 設定追従の 3 値を [/settings](/settings) で個人ごとに選べる。既定は OS 設定追従で、暗い会場 / 夜間に自動で目に優しいダークパレットに切り替わる。詳細は [11-theme-and-display.spec.md](11-theme-and-display.spec.md)

### 5.4 運用の考え方

- 操作ログ（バスト / 席移動 / シーズン切替など）は内部に記録される
- 障害時は運営者が画面を再読み込みすることで現状確認できる
- 監視ダッシュボード / アラート機能は本仕様書時点では未整備。運営者が手動で確認する

## 7. 既知の全体制約

業務に影響する範囲だけを箇条書きで:

- **対象規模**: 6 卓以下 / 20 人前後のサークル開催を想定。7 卓以上の運用は対応外（卓間バランシングのルールが変わるため）
- **多言語対応**: 日本語のみ。英語・他言語の表示には未対応
- **モバイルアプリ（ネイティブ）は提供していない**: Web ブラウザのみ。ただし **PWA 化（ホーム画面追加）には対応**しており、専用アプリのような起動が可能
- **完全オフライン運用は対応外**: 数秒〜数分の一時的通信障害は耐えるが、モバイル回線が完全に死んでいる会場（深い地下 / 山間部）は対応外。優勝者確定は通信必須
- **監視 / アラートは未整備**: 障害発生時は運営者が手動で確認する
- **観戦モードはトグル単位の opt-in**: 運営者が公開判断したトーナメントだけを公開 URL で読み取り専用閲覧できる（[10-spectate-mode.spec.md](10-spectate-mode.spec.md)）。短命 token / 限定公開などの高度な制御は未実装
- **リバイ・アドオンの実行操作は未実装**: ストラクチャに量フィールドはあるが、実行 UI はない
- **賞金計算（ICM 含む）は未実装**
- **リングゲーム（トーナメント外の自由参加ゲーム）の管理は未対応**: 運営者が卓を空けて閉じることはできるが、空けた卓のチップ・ブラインド・席はアプリでは管理しない（[05-seating-and-balancing.spec.md](05-seating-and-balancing.spec.md)）
- **名前のみで代理受付した参加者は本人アカウントに紐づけ直せない**: 運営者管理専用のままで、シーズン戦績や順位の集計対象にはならない（[04-tournaments.spec.md](04-tournaments.spec.md)）
- **音声通知のカスタム音源アップロードは未実装**: デフォルト音源 2 種類のみ
- **招待リンクの最大利用回数 UI は未実装**: 現状は上限なしで運用
- **受付 QR の拡散による意図しない加入**: 受付 QR を知る通常アカウントは、受付するだけでサークルの一般メンバーになる。QR を不特定多数の目に触れる場所へ出さない運用が前提で、誤加入はオーナーの除外で事後回収する（[02-circles-and-membership.spec.md](02-circles-and-membership.spec.md)）
- **除外は「受付可能なトーナメントが残っていると効かない」**: 除外対象者の参加記録が受付前・配席中・進行中・一時停止のトーナメントに残っていると、本人が受付画面を開き直すだけで再加入する。除外を確実にしたい場合は該当トーナメントを先に終了させる
- **受付経由の自動加入を無効にする設定はない**: サークル側で ON/OFF を切り替えることはできない
- **加入経路の履歴が残らない**: 「誰がいつどのトーナメント経由で加入したか」は記録されない
- **テンプレート管理者の付与・剥奪 UI は未実装**: 運営チームが直接データベース上で設定する必要がある
- **Web Share API は対応端末のみ**: 結果カード（優勝カード / シーズン首位カード）は全端末で「画像を保存」が使えるが、OS シェアシート経由の 1 タップ送信は iOS Safari / Android Chrome 等の Web Share API 対応端末のみ。非対応端末では画像保存後に手動で SNS にアップロード
- **過去シーズン側の結果カードは未提供**: 履歴は閲覧のみ。過去シーズンの首位カード PNG ダウンロードは現状提供していない（現在シーズンのみ）
- **シーズン自動切替（毎月 1 日 / 4 月 1 日 など）は未実装**: 運営者の手動操作のみ
- **複数端末（PC + スマホ）からの同時操作の検出は未対応**: 同一ブラウザ内のタブ同時オープンには警告が出るが、別端末からの並行操作は検出されない
- **結果カード背景画像の設定はオーナー限定**: サークル単位で 2 枚（優勝者用・シーズン首位用）の背景画像を設定でき、運営担当者・一般メンバーは閲覧のみ。per-tournament 個別設定は未対応
- **トップ画面 note 記事リンクは環境変数依存**: URL を環境変数（`NEXT_PUBLIC_NOTE_*`）で管理し未設定なら非表示。fork 直後でも安全なフォールバックだが、リンクを出すには運営者側の設定作業が必要
- **テーマ設定は端末ごと（個人 preference）**: ライト / ダーク / OS 設定追従の切替は端末のブラウザに保存され、同じアカウントの別端末には同期されない。サークル単位の強制やアカウント単位の横断同期は未対応（[11-theme-and-display.spec.md](11-theme-and-display.spec.md)）
- **テーマのカスタム配色は未対応**: 用意しているのはライト / ダーク / OS 設定追従の 3 種類のみ。セピア / ハイコントラスト / カスタム配色は提供していない
- **結果カードの共有画像（PNG）はテーマ切替と別系統**: シェア先環境に依存しないよう、結果カードのテキストテーマ（ライト / ダーク）は **サークル単位** で別途切り替える（[02-circles-and-membership.spec.md](02-circles-and-membership.spec.md) / [08-season-stats.spec.md](08-season-stats.spec.md)）

詳細は各個別 spec の「6. 既知の制約・未対応事項」を参照。
