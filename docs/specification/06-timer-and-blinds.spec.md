# タイマー・ブラインド進行 業務仕様書

## 1. 概要

トーナメントの **タイマー** とそれに連動した **ブラインド進行** を管理する機能。すべての端末で同じ時刻が表示されるように **自動更新（同期）** され、運営者の PC・参加者のスマホ・会場ディスプレイのどこから見ても同じブラインドレベルになる。タイマーは自動進行（レベル時間切れで次レベル）と手動操作（一時停止・再開・巻戻し・次レベル）の両方に対応している。進行中でも運営者が **レベル時間を変更** したり **新しいレベルを末尾に追加** したりできる。会場の大画面投影には **全画面表示** モードを使う。通信が切れた場合は最終時刻と「接続切れ」の表示が出る。主に運営者ダッシュボード（[/tournaments/[tid]](/tournaments/%5Btid%5D)）と参加者向け表示（[/tournaments/[tid]/live](/tournaments/%5Btid%5D/live)）で使う。

## 2. 想定利用シーン

### 2.1 ペルソナ

- **運営担当者**: タイマーを操作し、休憩を入れたり進行を調整する人
- **参加者**: スマホで現在のブラインドと残り時間を確認する人
- **会場運営**: 会場の大型ディスプレイにタイマーを投影して全員に見せる人

### 2.2 シナリオ

#### 2.2.1 平常系: トーナメント開始から終了まで

席決定後、運営担当者がダッシュボードで「トーナメント開始」を押す → タイマーが Lv 1 から動き出す → 各端末で同じ残り時間が表示される → レベル時間が切れると自動で Lv 2 に進む（音声通知も鳴る）→ 中盤で Lv 5 が休憩レベルなら、画面が「休憩中」表示に変わる → 最終的に残り 1 人になると Winner 演出 → 自動終了。

#### 2.2.2 平常系: 進行中の一時停止と再開

会場で予期せぬ中断（食事休憩・トラブル対応など）が発生した場合、運営担当者がダッシュボードの「一時停止」ボタンを押す → タイマーが止まり、状態が「一時停止中」になる → 全端末で「一時停止中」と表示される → 再開時に「再開」ボタンを押すとタイマーが再開する → 一時停止していた時間はカウントから差し引かれる。

#### 2.2.3 平常系: レベル時間の動的変更

進行中、運営担当者が「Lv 7 の時間を 20 分 → 15 分に短縮したい」と判断 → ストラクチャ表示カードで Lv 7 の時間欄の鉛筆アイコンを押す → 入力フィールドに変えて新しい値を入力 → 保存 → 全端末の残り時間が新値ベースで再計算され、約 1 秒以内に反映される。

#### 2.2.4 平常系: ストラクチャの最終レベルに到達したのに優勝者未確定

事前作成したストラクチャが Lv 12 で終わるが、Lv 12 終了時点でまだ優勝者が決まらない場合、運営担当者が「+ レベル追加」ボタンで新しい Lv 13 を末尾追加 → SB / BB / アンティ / 時間 / 休憩フラグを入力 → 保存 → タイマーが続行可能になる。

#### 2.2.5 失敗系: 通信切断

運営者の PC が一時的にネット切断 → 画面に「接続切れ」のバッジと最終同期時刻が表示される → 運営者は混乱せず、復旧を待つ → 復旧後は自動で最新状態に同期される。

#### 2.2.6 運用系: 全画面表示で会場投影

運営者ダッシュボードで「全画面表示」ボタンを押す → ブラウザのアドレスバー等が消えて、タイマー部分が画面いっぱいに表示される → 会場の大型ディスプレイに投影 → 全卓から視認可能になる → 戻すときは Esc キーまたは「全画面解除」ボタン。

## 3. 機能要件

### 3.1 タイマーの基本表示

#### 3.1.1 何ができる機能か

- ダッシュボード中央のタイマー表示で、現在のレベル名・残り時間・SB / BB / アンティ・休憩フラグを表示
- 残り時間は MM:SS 形式の大きなフォントで、遠くからでも視認できる
- 全端末で同じ残り時間が同期される（自動更新）
- 端末のクロックではなく、サーバ時刻を基準に計算される

#### 3.1.2 誰が・いつ使うか

- 全ユーザーが、現在のブラインドと残り時間を確認したいとき

#### 3.1.3 なぜこの機能が必要か（Why）

「複数テーブル進行時に PC 画面が見えない席で、ブラインドの変化に気付けない」課題への直接解決。すべての端末でリアルタイムに同じ時刻を表示することで、参加者がスマホで常時確認できる。

#### 3.1.4 設定項目とその意味

該当なし（自動表示）。レベルの内容はストラクチャで決まる（[03-structures-and-templates.spec.md](03-structures-and-templates.spec.md)）。

#### 3.1.5 注意点・制約

- 端末のクロックがずれていてもサーバ時刻基準のため正確
- 通信切断時は最終同期時刻が表示される（後述）

### 3.2 トーナメント開始 / 一時停止 / 再開

#### 3.2.1 何ができる機能か

- 席決定後の運営者ダッシュボードに「トーナメント開始」ボタンが表示される
- 進行中は「一時停止」ボタンと「再開」ボタンが切り替わる
- 一時停止中はタイマーが止まり、全端末で「一時停止中」が表示される
- 一時停止していた時間はレベルの累積時間から差し引かれる

#### 3.2.2 誰が・いつ使うか

- 運営担当者・オーナーが進行を制御したいとき
- 食事休憩・トラブル対応・ハンド長期化時の介入

#### 3.2.3 なぜこの機能が必要か（Why）

サークル運営では予期せぬ中断が発生する（食事・電話・参加者の遅延など）。一時停止ができることで、ストラクチャ通りの「実プレイ時間」を保ったまま中断・再開できる。

#### 3.2.4 設定項目とその意味

該当なし（ボタン操作のみ）。

#### 3.2.5 注意点・制約

- 一般メンバーは操作不可
- 一時停止中の累積時間は次レベル遷移でリセット

### 3.3 自動レベル進行（auto-advance）

#### 3.3.1 何ができる機能か

- レベル時間が満了すると、自動的に次のレベルに進む
- ブラインドアップ時に音声通知が鳴る（[07-audio-notifications.spec.md](07-audio-notifications.spec.md) 参照）
- 休憩レベルへの遷移も自動で行われ、画面が「休憩中」表示に切り替わる
- 最終レベルに到達した状態では auto-advance しない（レベル末尾追加 or 手動進行が必要）

#### 3.3.2 誰が・いつ使うか

- 運営者は基本的に何もしない（自動進行）

#### 3.3.3 なぜこの機能が必要か（Why）

運営者がレベル切替を毎回手動でやらなくても、ストラクチャ通りに進行できるようにするため。

#### 3.3.4 設定項目とその意味

該当なし。

#### 3.3.5 注意点・制約

- 自動進行は運営者ロールの端末でのみ実行される（参加者側の端末では発火しない）
- ネット切断時は自動進行が遅れる場合がある（復旧後に同期）

### 3.4 手動レベル進行（次レベル / 巻戻し）

#### 3.4.1 何ができる機能か

- 「次レベル」ボタンで強制的に次のレベルに進める
- 「巻戻し」ボタンで前のレベルに戻せる
- 手動進行時は音声通知が鳴らない（誤操作で予期せず鳴らないため）

#### 3.4.2 誰が・いつ使うか

- 運営者が「予定より早く次に行きたい」「ミスでレベルを進めすぎたから戻したい」と判断したとき

#### 3.4.3 なぜこの機能が必要か（Why）

ストラクチャはあくまで目安で、当日の進行に合わせて柔軟に調整できる必要がある。手動操作も一時停止状態のまま正しく動くよう、内部の累積時間管理が整理されている。

#### 3.4.4 設定項目とその意味

該当なし。

#### 3.4.5 注意点・制約

- 一般メンバーは操作不可
- 巻戻しはレベル 0（受付前）には戻れない

### 3.5 レベル時間の動的変更

#### 3.5.1 何ができる機能か

- ストラクチャ表示カードで、各レベルの時間欄に鉛筆アイコンが表示される
- 鉛筆を押すと入力フィールドに変わり、新しい時間（分単位）を入力 → 保存
- 保存後、全端末の残り時間が新値ベースで再計算される
- 進行中レベルの時間も変更可能（即座に反映）
- 過去レベル（既に終わったレベル）と終了状態では編集不可

#### 3.5.2 誰が・いつ使うか

- 運営担当者が「会場の制限時間が押している → 後半のレベルを短縮したい」と判断したとき
- 「想定より人数が少ない → ブラインドを早送りしたい」場合

#### 3.5.3 なぜこの機能が必要か（Why）

サークル運営では会場の時間制約・参加人数の変動でストラクチャを調整したいケースが頻発する。事前に作ったストラクチャを開催中に動的に変えられることで、運営の柔軟性が大きく向上する。

#### 3.5.4 設定項目とその意味

| 項目 | 入力形式 | 推奨 / 既定値 | 業務上の意味 |
| --- | --- | --- | --- |
| レベル時間 | 整数（分単位、内部は秒） | 元の値 | このレベルが続く時間 |

範囲: 1 秒〜86400 秒（24 時間）。実用上は 1 分〜30 分程度。

#### 3.5.5 注意点・制約

- 過去レベルと終了状態は編集不可（鉛筆アイコンが表示されない）
- 一般メンバーは編集不可
- 編集すると全端末の残り時間が即時に再計算される

### 3.6 レベル末尾追加（append blind level）

#### 3.6.1 何ができる機能か

- 進行中のトーナメントで、ストラクチャ表示カード末尾の「+ レベル追加」ボタンで新しいレベルを末尾追加
- 入力項目: SB / BB / アンティ / レベル時間（分）/ 休憩フラグ
- 保存後、現在のストラクチャに新レベルが追加される
- 自動進行は新レベルでも動く

#### 3.6.2 誰が・いつ使うか

- 運営担当者が「事前作成したストラクチャの最終レベルに到達したが、まだ優勝者が決まっていない」場合

#### 3.6.3 なぜこの機能が必要か（Why）

ストラクチャは事前に作るが、実際の進行は人数・スタック量によって長短が変わる。最終レベルで張り付くと SB / BB / アンティが固定されたまま、決着がつくまで時間が伸びる問題があった。末尾追加で「もう 1 段強いレベル」を追加することで、決着を促進できる。

#### 3.6.4 設定項目とその意味

| 項目 | 入力形式 | 推奨 / 既定値 | 業務上の意味 |
| --- | --- | --- | --- |
| SB | 0 以上の整数 | 直前 BB の 0.5 倍程度 | スモールブラインド額 |
| BB | 0 以上の整数 | 直前 BB の 1.5〜2 倍 | ビッグブラインド額 |
| アンティ | 0 以上の整数 | 直前 BB の 0.1〜0.2 倍 | 全員払うアンティ |
| レベル時間（分） | 整数（分単位） | 5〜10 分程度 | このレベルの時間 |
| 休憩フラグ | チェックボックス | OFF | 休憩レベルかどうか |

#### 3.6.5 注意点・制約

- 1 トーナメントあたりの最大レベル数は 50（暴走防止）
- 一般メンバーは追加不可
- 終了状態では追加不可

### 3.7 全画面表示

#### 3.7.1 何ができる機能か

- 運営者ダッシュボードに「全画面表示」ボタンがあり、押すとブラウザの全画面 API でアドレスバー・タブが消える
- 解除は Esc キーまたは「全画面解除」ボタン
- 全画面中もタイマー進行・操作は継続される

#### 3.7.2 誰が・いつ使うか

- 会場の大型ディスプレイにタイマーを投影したいとき
- ノート PC・タブレットを会場の卓に置いて全員から見せるとき

#### 3.7.3 なぜこの機能が必要か（Why）

「全テーブルの全参加者が任意のタイミングで現在のブラインドを確認できる」を担保するため、会場の大画面投影に対応している。投影時はブラウザの UI を消すことで視認性が最大化される。

#### 3.7.4 設定項目とその意味

該当なし（ボタン操作のみ）。

#### 3.7.5 注意点・制約

- ブラウザによって全画面 API の挙動が微妙に異なる（一部のスマホブラウザは未対応の場合あり）
- 全画面中も別端末からの自動更新は受け取れる

### 3.8 接続切断 UI

#### 3.8.1 何ができる機能か

- ネットワーク切断時、画面に「接続切れ」のバッジが表示される
- バッジの近くに最後の同期時刻が表示される
- タイマー表示は最後の値で固定される（誤情報を出さない）
- 復旧すると自動で同期して通常表示に戻る

#### 3.8.2 誰が・いつ使うか

- 全ユーザーが、ネットワーク不調時に「画面が止まっているのか、ネットが切れているのか」を識別したいとき

#### 3.8.3 なぜこの機能が必要か（Why）

「ネット切断時に何が起きているのか分からない」と運営の判断が遅れる。明示的に切断を表示することで、参加者・運営者が「待つ」「移動して回線改善」などの判断をしやすくする。誤った時刻を表示し続けるよりも、最終時刻 + 接続切れの方が混乱を防ぐ。

#### 3.8.4 設定項目とその意味

該当なし（自動表示）。

#### 3.8.5 注意点・制約

- 切断検知は数秒のラグがある場合がある
- ブラウザのオフライン保存により、短時間の切断ではアプリは動き続ける（最終同期時刻で判別）

### 3.9 補助情報カード（次の休憩 / 平均持ち点 / 残人数）

#### 3.9.1 何ができる機能か

- 運営者ダッシュボードの右列に 3 つのカードが表示される:
  - **次の休憩までの時間**: 現在から次の休憩レベルまでの予想時間
  - **平均持ち点**: 残存参加者の平均スタック量
  - **残人数**: 現在のバスト前参加者数

#### 3.9.2 誰が・いつ使うか

- 運営担当者が、進行のペースや参加者状況を把握したいとき
- 「あと何分くらいで休憩か」「卓に持ち点が偏っていないか」を確認

#### 3.9.3 なぜこの機能が必要か（Why）

タイマーだけでは進行の俯瞰がしづらい。補助情報を 1 画面で確認できることで、運営者が「次の休憩を前倒しで入れる」「人数差が広がっているから声かけ」など、判断しやすくなる。

#### 3.9.4 設定項目とその意味

該当なし（自動表示）。

#### 3.9.5 注意点・制約

- 平均持ち点はトーナメントの初期持ち点 × 残人数 ÷ 残人数 で算出（リバイ・アドオンの実行操作が未実装のため、リバイ済みの実態は反映されない）
- 状態遷移時にカードが消えないよう、準備中・進行中・終了でレイアウトが変わらない設計

## 4. 権限・認可

### 4.1 ロール別操作マトリクス

| 操作 | オーナー | 運営担当者 | 一般メンバー | ゲスト（匿名） |
| --- | --- | --- | --- | --- |
| タイマー閲覧 | ○ | ○ | ○ | ○ |
| トーナメント開始 | ○ | ○ | × | × |
| 一時停止 / 再開 | ○ | ○ | × | × |
| 次レベル / 巻戻し（手動進行） | ○ | ○ | × | × |
| レベル時間の変更 | ○ | ○ | × | × |
| レベル末尾追加 | ○ | ○ | × | × |
| 全画面表示の切替 | ○ | ○ | △ | △ |
| 補助カードの閲覧 | ○ | ○ | △ | △ |
| 接続切断 UI の表示 | ○ | ○ | ○ | ○ |

凡例: ○ 可 / × 不可 / △ 参加者向け表示にも基本情報は出るが、運営者ダッシュボードの 3 カード詳細は表示されない（タイマー・自席・残人数は出る）

### 4.2 ロール定義（spec 内の文脈で）

- **オーナー / 運営担当者**: タイマーの操作・レベル時間の変更・末尾追加など、進行全般を制御
- **一般メンバー**: 参加者向け表示でタイマーと自席を確認するだけ
- **ゲスト（匿名）**: 受付完了画面までで止まり、live 画面には進まない

### 4.3 補足

- タイマーの「閲覧」はサークル所属に関係なく、トーナメント参加者なら誰でも可能
- 「操作」は運営担当者・オーナーのみ

## 5. 非機能要件（業務観点）

### 5.1 パフォーマンス（体感）

- ボタン押下から全端末への反映まで 1〜2 秒以内
- 自動進行のラグは 1 秒以内
- 残り時間表示は 1 秒間隔で更新（ジャンプはなし）
- 通信状態の良い環境では遅延の体感はない

### 5.2 セキュリティ（運用方針）

- タイマーの操作権限は運営担当者・オーナーのみ
- 不正な操作（参加者が一時停止を強制するなど）はアクセス権で弾かれる
- レベル時間の変更は内部の操作記録に残る

### 5.3 使いやすさ / アクセシビリティ

- タイマー文字は遠見に対応（PC で 10rem サイズ）
- ボタンはアイコン化＋ホバーで意味がわかる
- スマホ・タブレットでも視認性を保つレイアウト
- 全画面 API は標準 Web API のためキーボード操作で解除できる

### 5.4 信頼性 / エラー時の挙動

- 通信切断時は明示的にバッジ表示
- 同時複数の運営者操作はまとめて確定（途中失敗で何も変わらない）
- レベル時間の変更は配列の書き戻し処理で、競合時は後勝ち
- ストラクチャの level 配列の上限（50）を超える追加は弾かれる

### 5.5 保守性 / 運用負担

- レベル時間の変更は途中レベルにも適用できるため、当日の運営調整が簡単
- 末尾追加は「最後の手段」として設計されており、頻繁に使わない想定
- 一時停止累積時間は内部で正確に管理されるため、運営者は意識しない

### 5.6 互換性

- 全画面 API はモダンブラウザでサポート
- 既存トーナメントは現在のレイアウトに自動移行される
- 過去のレベル時間変更履歴は内部の操作記録に残る

### 5.7 運用 / 観測性

- タイマーの開始・一時停止・再開・レベル進行・時間変更・末尾追加はすべて操作記録に残る
- 障害時は再読み込みで復旧
- 通信切断時は「最終同期時刻」が表示されるため、運営者は何分前まで同期できていたかを把握できる

## 6. 既知の制約・未対応事項

- **ストラクチャの先頭・中間にレベル挿入する操作はない**: 末尾追加のみ
- **リバイ・アドオンの実行操作は未実装**: 平均持ち点が実態と乖離する可能性あり（量フィールドはストラクチャに記録されている）
- **Cloud Functions による定期再計算は未利用**: クライアント側でサーバ時刻基準の差分計算を行う設計
- **レベル時間の最大値は 86400 秒（24 時間）**: 防衛線として設定。実用上は不要
- **巻戻しの上限**: レベル 1 の最初までは戻れない
