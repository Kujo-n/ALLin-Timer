# PWA・アプリシェル・端末対応 業務仕様書

## 1. 概要

ALLin-PokerTimer を **スマートフォンのホーム画面アイコンから「アプリのように」起動** できるようにする機能群。会場 Wi-Fi が不安定な環境でも、運営者が会場到着後にホーム画面アイコン 1 タップでタイマー画面に到達でき、進行中の一時的な通信障害でも画面が真っ白にならないようにする。トップ画面でホーム画面追加を促すバナーが出るほか、iOS Safari など個別の OS ごとの追加手順を文章で案内する。タイマー画面に長く留まるシーンでは画面消灯防止と横向きロックも有効になる。インストール後はブラウザのアドレスバーやタブが消え、専用アプリのような見た目で起動できる。主に [/](/) のトップ画面、運営者ダッシュボード（[/tournaments/[tid]](/tournaments/%5Btid%5D)）、参加者向け表示（[/tournaments/[tid]/live](/tournaments/%5Btid%5D/live)）で体感できる。

## 2. 想定利用シーン

### 2.1 ペルソナ

- **会場運営する運営担当者**: 月 1〜2 回の開催で、毎回ブラウザのブックマークを開いている人。会場到着時の起動所作を最小化したい
- **会場プロジェクタ投影担当者**: ノート PC やタブレットで会場の大画面にタイマーを投影中、画面が消えたり横向きが崩れたりするのを防ぎたい人
- **不安定な会場で参加する人**: モバイル回線で接続中、地下の電波弱い会場や瞬断のある場所で「画面が固まったまま」になるのを避けたい人
- **複数端末を所持する人**: 同じ運営者が PC + スマホで同じトーナメント画面を開きそうになるとき、誤操作のリスクを警告で気付きたい人

### 2.2 シナリオ

#### 2.2.1 平常系: 初回トップ画面でホーム画面に追加

運営担当者 A さんが [/](/) を Chrome（Android）で開く → 画面に「ホーム画面に追加」のバナーが表示 → 「インストール」ボタンを押す → ブラウザ標準の確認ダイアログ → ホーム画面にアイコンが追加される → 次回からアイコンタップで standalone モード（ブラウザの URL バーやタブが消えた表示）で起動する。

#### 2.2.2 平常系: iOS Safari でのホーム画面追加案内

iPhone のオーナー B さんが Safari で [/](/) を開く → 「ホーム画面に追加するには、Safari の共有メニュー（中央下のアイコン）から『ホーム画面に追加』を選んでください」というテキスト案内が表示される → B さんは案内通りに操作してホーム画面に追加 → アイコンタップで standalone 起動。

#### 2.2.3 失敗系: 進行中の一時通信障害

運営担当者 A さんがタイマー進行中、会場のモバイル回線が数秒切断 → 画面に「通信が切れました」のバナーと最終同期時刻が表示される → タイマーは止まらず、ブラインドレベルの自動進行も continue する（次レベルへの切替が pending として queue に乗る）→ 通信回復で自動的に同期され、バナーが消える。

#### 2.2.4 運用系: 画面消灯防止と横向きロック

運営担当者 A さんがノート PC を会場の大画面に投影 → タイマー画面で「開始」を押す → アプリが画面消灯防止（OS / ブラウザの省電力で勝手に画面が暗くならない）と横向きロックを有効化 → 投影中もタイマーが安定して見える → トーナメント終了 / タブ離脱時は自動的に解除される。

#### 2.2.5 失敗系: 複数タブで同じ画面を開いてしまった

運営担当者 A さんが誤って同じ画面を 2 つのタブで開く → 後から開いたタブに「別のタブで同じ画面が開いています。操作はどちらか一方で行ってください」という警告が表示される → A さんは片方のタブを閉じる。

#### 2.2.6 運用系: しばらく使わなかった後の起動

iOS の運営者 B さんが 1 ヶ月以上アプリを開かなかった → ホーム画面アイコンをタップ → 起動時に最新版のアプリ部品が再取得される → 起動は通常よりやや遅いが（数秒）、最新のタイマー画面が表示される。

## 3. 機能要件

### 3.1 ホーム画面追加（PWA インストール）

#### 3.1.1 何ができる機能か

- スマートフォン・PC のホーム画面 / デスクトップに、ALLin-PokerTimer のアイコンを追加できる
- アイコンをタップすると、ブラウザの URL バーやタブが見えない **standalone モード**（専用アプリのような表示）で起動する
- アプリ名（ALLin-PokerTimer）・テーマカラー・起動時の背景色が定義済みで、OS のスプラッシュ画面に反映される

#### 3.1.2 誰が・いつ使うか

- 月 1〜2 回 ALLin-PokerTimer を使う運営担当者・オーナーが、会場到着時の起動所作を短縮したいとき
- 参加者がトーナメントへの再アクセスを簡単にしたいとき（任意）

#### 3.1.3 なぜこの機能が必要か（Why）

ブラウザのブックマークから毎回起動する所作（ブラウザを開く → ブックマーク → タップ）が、月 1〜2 回しか使わないアプリでは摩擦が大きい。ホーム画面のアイコンから 1 タップで起動できれば、会場到着時の準備が早い。standalone モードで起動すると、URL バーやタブの分だけタイマーが大きく表示できる利点もある。

#### 3.1.4 設定項目とその意味

該当なし（インストール時に OS 標準の確認ダイアログが出るのみ）。アプリ側でカスタマイズできる項目はない。

#### 3.1.5 注意点・制約

- **iOS Safari** はブラウザ自動の追加促進ダイアログを出さない。共有メニューから手動で追加する仕様（テキスト案内が表示される）
- **Android Chrome** は条件を満たすと自動でインストール促進バナーを出す（後述）
- **Desktop Chrome / Edge** ではアドレスバー右端のインストールアイコンから追加できる
- インストール後もブラウザ版の利用は続けられる（強制ではない）
- iOS では **約 7 日間アプリを開かないと内部のキャッシュが自動削除される** OS の仕様がある。月 1 回開催のサークルでは毎回起動時に部品が再取得される（数秒の起動遅延）

### 3.2 インストール促進バナー（トップ画面 / 全ユーザー）

#### 3.2.1 何ができる機能か

- [/](/) のトップ画面の上部に「ホーム画面に追加」のバナーが表示される
- Android Chrome 等の対応ブラウザでは「インストール」ボタンを押すと OS 標準のインストールダイアログが開く
- iPhone Safari ではバナーの代わりに「共有メニューから追加」というテキスト案内が表示される
- バナー右上の「× 閉じる」を押すと **30 日間** 表示されない（dismiss）
- 既にインストール済み（standalone モードで起動中）の端末では表示されない

#### 3.2.2 誰が・いつ使うか

- 全ユーザー（運営者 / メンバー / 参加者）がトップ画面を訪問したとき
- 運営担当者を主な対象としつつ、メンバー・ゲストにも表示される（「× 閉じる」で簡単に消せるため誤表示のコストは低い設計）

#### 3.2.3 なぜこの機能が必要か（Why）

「PWA 化されたことを運営者が気付かない」ままだと、ホーム画面追加の導線が活きない。トップ画面という運営者が必ず通る場所にバナーを置くことで、初回だけでも気付いてもらえる。会場のダッシュボード画面ではバナーを出さない設計（運営中の邪魔にならないため）。

#### 3.2.4 設定項目とその意味

| 項目 | 入力形式 | 推奨 / 既定値 | 業務上の意味 |
| --- | --- | --- | --- |
| Dismiss 期限 | 自動（× を押した時刻から計算）| 30 日 | 一度閉じたら 30 日表示しない（必要に応じて再表示） |

#### 3.2.5 注意点・制約

- バナーは [/](/) のみで表示。運営者ダッシュボードや参加者向け表示には出さない
- 現状、運営者だけでなく一般メンバー・ゲストにも表示される（誤表示のコストが「× で閉じるだけ」と低いため、ロール限定はしていない）
- iPhone Safari は「ブラウザに追加促進機能がない」OS 仕様のため、テキストでの手順案内のみ
- インストール済みかどうかの判定は、ブラウザの API（display-mode: standalone）に依存

### 3.3 タイマー進行のオフライン耐性

#### 3.3.1 何ができる機能か

- タイマー進行中に通信が一時的に切れた場合、画面に **「通信が切れました」のバナー** と最終同期時刻が表示される
- バナー表示中もタイマーの残り時間表示は継続し、ブラインドレベルの **自動進行も継続する**（通信が戻ったときに同期される）
- 通信回復後はバナーが消え、最新状態に自動同期される
- 詳細仕様（オフライン時のレベル進行ロジック・手動操作・end-of-tournament の挙動）は [06-timer-and-blinds.spec.md](06-timer-and-blinds.spec.md) を参照

#### 3.3.2 誰が・いつ使うか

- 不安定な会場（地下・トンネル隣接・モバイル回線）で運営担当者が進行を継続したいとき
- 参加者が live 画面で「画面は固まっているが、ネットが切れているだけ」を識別したいとき

#### 3.3.3 なぜこの機能が必要か（Why）

会場 Wi-Fi 不在 / モバイル回線の瞬断で「タイマーが止まる」「ブラインドが上がらない」事象が起きると、運営者が混乱しトーナメント進行が中断する。一時的な通信障害でもタイマーが進み続け、後で正しく同期される設計にすることで、「会場でタイマーを止めない」核心価値を維持する。

#### 3.3.4 設定項目とその意味

該当なし（自動処理）。

#### 3.3.5 注意点・制約

- **トーナメント終了（優勝確定）操作は通信回復後に実施** することが推奨。終了処理は集計の正しさを保つため通信必須
- 1 端末の運営者が複数の操作（次レベル / 一時停止）を連続して行うと、通信回復時に順序通りに反映される（後勝ちではなく操作順）
- 詳細は [06-timer-and-blinds.spec.md](06-timer-and-blinds.spec.md) を参照

### 3.4 デバイス制御（画面消灯防止 / 横向きロック / 音声解除の自動化）

#### 3.4.1 何ができる機能か

- タイマー進行中（運営者ダッシュボード / 参加者向け表示）に **画面消灯防止** が有効化され、OS の省電力で画面が勝手に暗くならない
- ホーム画面追加（standalone モード）で起動した端末では **横向きロック** も試行され、誤って縦に回しても表示が崩れない
- タイマー開始ボタンを押した瞬間に音声再生の許可が取得される（運営者の意図しない無音状態を予防）
- 端末・ブラウザが画面消灯防止 / 横向きロックに対応していない場合は **「画面 off にしないでください」「横向きで投影してください」のテキスト案内** が表示される

#### 3.4.2 誰が・いつ使うか

- 運営担当者・オーナーが会場プロジェクタ投影中、画面が暗くなったり縦に回ったりするのを防ぎたいとき
- 一時停止が長引くシーン（食事休憩中）でも、再開時にタイマーが消えていないようにしたいとき

#### 3.4.3 なぜこの機能が必要か（Why）

会場の大画面投影中に画面が消灯すると、参加者全員から見て「タイマーが消えた」状態になり、運営の信頼性が損なわれる。OS の省電力設定を毎回手動で外す手間も大きい。アプリ側で自動的に消灯防止と横向きロックを掛けることで、運営者は何も意識せずに投影できる。

#### 3.4.4 設定項目とその意味

該当なし（自動有効化）。

#### 3.4.5 注意点・制約

- 画面消灯防止は **タイマーが進行中** のときのみ有効。準備中・終了後は OS の省電力に従う
- 横向きロックは **standalone モード（ホーム画面アイコン起動）** のときのみ動作。通常のブラウザタブでは効かない
- 一部の iOS Safari 旧バージョンは画面消灯防止 API に未対応。テキスト案内に倒れる
- バッテリー消費は通常のブラウザ表示と比べて若干増える（投影中は電源接続を推奨）

### 3.5 複数タブ同時オープンの警告

#### 3.5.1 何ができる機能か

- 同じ端末で同じ運営者ダッシュボードを **2 つ以上のタブ / ウィンドウ** で開くと、後から開いたタブに警告が表示される
- 警告の内容: 「別のタブで同じ画面が開いています。操作はどちらか一方で行ってください」
- 警告を無視して両方で操作することも可能（強制的に閉じはしない）

#### 3.5.2 誰が・いつ使うか

- 運営担当者が誤って同じ画面を複数タブで開いてしまったとき
- ブラウザの「最近閉じたタブを開く」操作で重複オープンしたとき

#### 3.5.3 なぜこの機能が必要か（Why）

複数のタブで同じ画面を同時に開くと、どちらかが古い情報を表示し続ける場合がある（ブラウザの内部キャッシュ仕様）。気付かずに古いタブで操作すると、運営者の意図と異なる結果になる可能性がある。明示的に警告することで、運営者が片方のタブに集中できる。

#### 3.5.4 設定項目とその意味

該当なし（自動表示）。

#### 3.5.5 注意点・制約

- 警告は表示するが、強制的にタブを閉じるなどの介入はしない
- 別端末（PC + スマホ）からの同時オープンは検出対象外（ブラウザ内部の検出機構の仕様）

## 4. 権限・認可

### 4.1 ロール別操作マトリクス

| 操作 | オーナー | 運営担当者 | 一般メンバー | ゲスト（匿名） |
| --- | --- | --- | --- | --- |
| ホーム画面に追加（インストール） | ○ | ○ | ○ | ○ |
| インストール促進バナーの閲覧 | ○ | ○ | ○ | ○ |
| インストール促進バナーの閉じる（30 日 dismiss）| ○ | ○ | ○ | ○ |
| iOS の手動追加案内の閲覧 | ○ | ○ | ○ | ○ |
| 通信切れバナーの閲覧 | ○ | ○ | ○ | ○ |
| 画面消灯防止 / 横向きロックの自動有効化 | ○ | ○ | ○ | ○ |
| 複数タブ警告の閲覧 | ○ | ○ | ○ | ○ |
| Service Worker の登録 / 更新 | ○（自動）| ○（自動）| ○（自動）| ○（自動）|

凡例: ○ 可 / × 不可

### 4.2 ロール定義（spec 内の文脈で）

- **全ロール共通**: 本 spec の機能はロールに関係なく、全ユーザーに対して同じように動作する
- **オーナー / 運営担当者**: タイマー進行中の画面消灯防止 / 横向きロックが特に重要なペルソナ
- **一般メンバー / ゲスト**: 参加者向け表示でも画面消灯防止が動作するため、自分の席を確認するのに便利

### 4.3 補足

- インストール促進バナーは **トップ画面 [/](/) のみ** で表示。役割によらず全ユーザーに表示される（誤表示コストが低いため）
- 画面消灯防止と横向きロックは「タイマーが進行中」など、特定の画面・状態でのみ動作する（バッテリー保護のため）

## 5. 非機能要件（業務観点）

### 5.1 パフォーマンス（体感）

- ホーム画面アイコンタップから standalone 起動までは **数秒以内**（初回 / 久しぶりの起動はやや遅め、毎日使うと早い）
- 通信切れバナーの表示は切断検知から **数秒以内**
- 画面消灯防止 / 横向きロックの有効化はタイマー開始から **1 秒以内**

### 5.2 セキュリティ（運用方針）

- インストール後も認証状態 / 権限はブラウザ版と同じ（ホーム画面アイコンから起動しても、改めてサインインが要らないだけ）
- インストール促進バナーは情報を取得しない（ローカルの dismiss 状態のみ保持）
- Service Worker は **アプリ自身のリソース** のみキャッシュ。サークル固有データ（参加者情報・トーナメント記録）は通常通りクラウド上のデータベース経由で取得される

### 5.3 使いやすさ / アクセシビリティ

- バナー / 案内テキストはスマホでも読みやすいフォントサイズ・コントラスト
- iPhone Safari ユーザーには「共有メニューから追加」の手順を文章で示す
- 画面消灯防止 / 横向きロックが効かない端末でもテキスト案内で代替手段が伝わる
- インストール促進バナーは「× 閉じる」で確実に消せる（dismiss 状態は 30 日間保持）

### 5.4 信頼性 / エラー時の挙動

- 通信切断時もタイマーは止まらない / 画面が真っ白にならない
- 通信回復時は自動同期されるため、運営者の手動操作なしに最新状態に戻る
- 複数タブで同じ画面を開いた場合の警告は「気付き」のみで、強制終了はしない（運営者の判断を尊重）

### 5.5 保守性 / 運用負担

- インストール後の更新は自動。アプリの新バージョンが配布されると、次回起動時にバックグラウンドで反映される
- 運営者がアイコンを再インストールする必要は基本的にない
- iOS の 7 日間自動削除に対しては起動時の自動再取得で対応（運営者は意識しなくてよい）

### 5.6 互換性

- **対応ブラウザ**: モダンブラウザ全般（Android Chrome / iOS Safari 16 以降 / Desktop Chrome / Edge / Firefox）
- iOS Safari は standalone モードのみ対応（フルスクリーンモードは非対応）
- Service Worker / 画面消灯防止 API / 横向きロック API は対応していない端末では自動的に無効化（テキスト案内に倒れる）
- 既存のブラウザ閲覧での動作は変わらない（インストールしないユーザーへの影響なし）

### 5.7 運用 / 観測性

- インストール完了 / 通信切れ / 画面消灯防止の有効化はアプリ内部の操作記録に残る
- 障害時は運営者が再起動 → ホーム画面アイコンから起動し直すことで、最新版のアプリが取得される
- 「ホーム画面に追加した」「会場で動作した」などの効果は運営者ヒアリングで確認

## 6. 既知の制約・未対応事項

- **完全オフライン運用は対応外**: モバイル回線が完全に死んでいる会場（地下深部 / 山間部）は対応外。Wi-Fi が無い会場でもモバイル回線で online 保持する前提
- **マスター機 1 台モード（運営者がメンバー / ゲストの代理受付）は未実装**: 通信障害下で運営者が代理操作する想定は将来 PRD で検討
- **観戦モード URL（外部の観客向け公開リンク）は未実装**: 別 PRD（PRD 04 候補）として後続
- **Web Push 通知は未実装**: iOS の制約（条件複雑 / 対応国限定）と必要性の低さで保留
- **インストール促進バナーのロール限定は未実装**: 現状は全ユーザーに表示。誤表示のコストが「× で閉じるだけ」と低いためロール限定をしていない
- **Service Worker のキャッシュ容量上限は OS 仕様**: iOS 約 50MB / Android 約 100MB。現状の本アプリは数 MB 規模で問題なし
- **複数端末（PC + スマホ）からの同時操作の検出は未対応**: 同一ブラウザ内のタブのみ検出
- **ブラウザのプライベートモード / シークレットウィンドウではインストール不可**: 通常モードで開く必要がある
