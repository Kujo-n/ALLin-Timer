# 用語ポリシー — 非エンジニア読者向け記事の書き方

このファイルは「非エンジニア読者向け記事」用の用語ポリシー。
**`docs/article/` 配下すべての記事に自動適用されるわけではない**。
適用対象は、記事の frontmatter で `terminology_policy_ref: ./conventions/terminology-policy.md`
（または等価な相対パス）を明示的に参照している記事のみ。

`docs/article/` 配下にはエンジニア読者向け記事（生成 AI を使ったアプリ開発記事 等）も
将来的に置かれるため、それらは本ポリシーを参照しない / 別ポリシーを参照する。

参照している記事を新規作成・更新する前に必ず本ファイルを読むこと。

## 前提

読者は **非エンジニア**（典型的にはサークル運営者）。ソフトウェア開発の技術用語を本文で使わない。
読者が知らない単語に出会った時点で離脱する前提で書く。

「自分（書き手）が読んで自然な文章」と「読者が読んで自然な文章」は別物。
迷ったら **「対面で説明するならどう言うか」** を基準にする
（本プロジェクトではポーカーサークルの仲間が想定読者）。

---

## 禁止語

本文で使ってはいけない語。やむを得ない場合は必ず日常語に言い換える。

### 技術スタック名（一切出さない）

- Firebase / Firestore / Authentication / Auth / Cloud Functions
- Next.js / React / TypeScript / Tailwind / Vercel
- GitHub Actions / CI / CD（運用の話でも本文には出さない）

### 実装用語（本文 NG）

- schema / validation / rule / transaction / atomic / consistent
- subscribe / snapshot / listener / onSnapshot / realtime sync
- repository / service / helper / wrapper / orchestrator
- mock / stub / fixture
- uid / docId / ref / collection / document / field
- API / endpoint / callback / webhook
- cache / session / token / cookie
- deploy / production / staging / environment
- migration / rollback

### 内部状態名（本文 NG）

| 内部名 | 本文での書き方 |
| --- | --- |
| `setup` | 受付前 |
| `seating` | 配席中 |
| `running` | 進行中 |
| `paused` | 一時停止 |
| `finished` | 終了済み |

### 実装側の言葉でユーザー対応していない語

| 避ける語 | 本文での書き方 |
| --- | --- |
| anonymous / anon | ゲスト |
| autoplay 制約 | ブラウザの仕様で最初に 1 タップが必要 |
| permission denied | 権限がありません |
| race condition | （言及しない、または「同時に操作したとき」） |

## 初出で説明が必要な略語

略語そのものは使ってよいが、**記事内で初めて出すときに必ず日本語の意味を添える**。

| 略語 | 初出時の表記例 |
| --- | --- |
| PWA | ホーム画面に追加できるアプリ（PWA） |
| TDA | トーナメントディレクター協会（TDA） |
| PD | プレイングディーラー（PD） |
| NLH | ノーリミットテキサスホールデム（NLH） |
| FT | ファイナルテーブル（FT） |

## 一般語として許容

説明なしで使ってよい語。読者が日常で目にしているはず。

- **デバイス系**: スマホ / PC / モニタ / プロジェクタ / ブラウザ / タブ
- **通信系**: URL / QR コード / Wi-Fi
- **アプリ操作系**: アプリ / アカウント / ログイン / メール / パスワード
- **外部サービス名**: Google / LINE / X
- **ポーカー用語**: ストラクチャ / ブラインド / バスト / バランシング / アンティ / レイトレジスト

## 言い換え辞書

| 避ける語 | 推奨表現 |
| --- | --- |
| 認証 | ログイン |
| ロール | 権限（オーナー / 運営担当 / 一般メンバー） |
| リアルタイム同期 | 自動で反映 / すぐに反映 |
| トランザクション | （言及しない） |
| スナップショット | （言及しない、または「保存」） |
| ログインセッション | ログイン状態 |
| クライアント / サーバ | （言及しない） |
| state / 状態遷移 | 受付前 / 配席中 / 進行中 / 一時停止 / 終了済み |
| インスタンス | （言及しない） |
| 同期する / 非同期 | （言及しない、または「自動で」） |

## 例外を作りたくなったとき

- 「この語は読者が知っているはず」と感じても、**まず置換できないか試す**
- どうしても置換できない場合は、本ファイルに追加して**本ポリシーを参照している記事全体で揃える**
- 1 記事限定の例外は作らない（本ポリシーを参照している記事間で語感がブレるため）
- そもそも本ポリシーが合わない読者層（例: エンジニア向け記事）の場合は、
  本ファイルを参照せず別の用語ポリシーを作る or 用語ポリシー無しで運用する

---

## 違反検知の運用

- 記事編集後にテキスト全文を眺めて、本ファイルの「禁止語」一覧と照合
- AI が記事を更新する場合、frontmatter の `terminology_policy_ref` が本ファイルを指していたら、
  本文を書く前に必ず本ファイルを読み込む
- 違反を見つけたら本ファイルの言い換え辞書を更新し、置換ルールを残す
